# 记一次学习 · 逐屏规格

> **这份文档回答:用户怎么把「我刚才碰过这个」记下来,以及记不成的时候屏幕上发生什么。**
> 覆盖 `S-HOME` `S-REC` `S-TL` 三屏。**这是整个产品唯一一块服务阶段 0 的功能** ——
> 阶段 0 的验收判据就是「自己用两周,每天记两个数」(`实施路径` §阶段 0 的验收),那两个数从这三屏产生。
>
> **不是**采集层的产品判断(在 [`模块 B · 采集层`](../modules/模块B-采集层.md))、**不是**接口签名(在 [`技术架构与接口契约`](../../technical/INDEX.md) §6.2)、
> **不是**原图的存储判据(在 [`原图存储：判据层与存储层`](../../technical/原图存储-判据层与存储层.md))。
> 全局约定在 [`总纲`](INDEX.md) §二。
>
> **基线:`origin/v1` @ `83b9632`,fetch 于 2026-09-01T14:00Z。**
> **状态:活跃。** 采集入口增删、离线队列行为变化、每日两个数字的口径变化,本文同一次改动内更新。

## 一、🔴 这一块只有一条硬规则

> **记录动作永不失败。**(`1.3.7.1`)

离线、识别服务挂了、额度用完了、骨架还没建好、没登录 —— **这一条记录都必须落下来**。
可以失败的只有它的**附加能力**(转写、识别、打标),失败时记录本身照样在,只是少了标签。

**判据**:任何一条「点了记录但什么都没留下」的路径都是违规。§六 的异常表里,每一行的「记录留住了吗」列必须是 ✅。

## 二、`S-HOME` 首页

**首页只干一件事:让「再记一条」的距离尽可能短。** 它不是仪表盘。

### 2.1 元素清单

| 区 | 元素 | 取值来源 | 为空时 | 可点 |
|---|---|---|---|---|
| 顶 | 离线细条 | 网络状态 | 在线时不显示 | 否 |
| 一 | **今天记了 {n} 条** | 本机 + 云端当日 `record_created` 计数 | 「今天还没记」 | 点进 `S-TL` 当天 |
| 一 | **今天有 {m} 次没记** | 用户自己点「本来该记但懒得记」的计数 | 显示 0 | 否 |
| 二 | **主按钮「记一条」** | —— | 常驻 | 是 → `S-REC` |
| 二 | 三个快捷:🎤 说 · 📷 拍 · ✍️ 写 | —— | 常驻 | 是 → `S-REC` 对应模式 |
| 三 | 「本来该记,但懒了」按钮 | —— | 常驻 | 是,点一次 `m+1` |
| 四 | 最近 3 条记录摘要 | 本机/云端最新 3 条 | 隐藏整个区 | 点进 `S-TL` |
| 五 | 「看盲区」入口 | —— | 骨架未就绪时仍显示,进去后是空态 | 是 → `S-BLIND` |

🔴 **首页不出现:覆盖率进度条、连续天数、任何百分比、任何评价性文字。** 只有两个计数和一个按钮(`总纲` §2.3)。

### 2.2 「本来该记,但懒了」这个按钮为什么在首页

它是阶段 0 两个数字里的第二个,而且**它衡量的是产品的摩擦,不是用户的懒**。
点一下就完,**不问原因、不填表单、不弹任何东西**,Toast「记下了」。

⚠️ **这个按钮永远不能被做成负面反馈**(不许出现「今天已经偷懒 3 次了」)。它只是计数。

### 2.3 状态

| 状态 | 屏幕 |
|---|---|
| 首次打开(零记录) | 一区显示「今天还没记」;四区隐藏;主按钮下方一行说明「随手记一句就行,不用写完整」 |
| 有数据 | 如上表 |
| 同步中 | 顶部细条「正在同步 {n} 条」 |
| 离线 | 顶部细条「离线中,已存在这台设备上」 |

## 三、`S-REC` 记一次

**一屏四种输入方式,不分页、不分 Tab 到用户找不到的地方。**

### 3.1 四种方式对照

| 方式 | 用在什么场景 | 要网吗 | 要额度吗 | 记录能不能落 |
|---|---|---|---|---|
| ✍️ **手写文本** | 任何时候 | ❌ | ❌ | 永远能 |
| 🎤 **语音** | 走路 / 刚下课 | 转写要 | 转写要 | **能** —— 转写失败也留音频引用与时间 |
| 📷 **拍照** | 纸质讲义 / 屏幕 | 识别要 | 识别要 | **能** —— 识别失败也留原图与时间 |
| 📥 **批量补录** | 离线回来 / 一次补一天 | 补传要 | 按条算 | **能** |

### 3.2 元素清单(手写模式)

| 元素 | 规则 | 为空时 |
|---|---|---|
| 输入框 | 单行起,自动增高,最多 6 行后内部滚动;**自动聚焦并唤起键盘** | 占位符:「刚才碰了什么?一句话就行」 |
| 来源输入 | 可选。下拉 + 可输入,记住最近 5 个来源名 | 不填就是空,**不猜、不填默认值** |
| 时间 | 默认此刻,可改到过去 | 不可改到未来 |
| 保存 | 主按钮「记下」;**输入框非空即可点** | 空时禁用 |

🔴 **来源只存名称与时间,不存任何课程内容**(边界:不存储任何培训机构的课程内容)。
🔴 **输入框不是题干框**:占位符、示例、帮助文案里**不许出现任何题目样子的文字**,否则用户会开始往里抄题。

### 3.3 语音模式

| 步骤 | 界面 | 规则 |
|---|---|---|
| 1 按下 | 大圆按钮 + 波形 + 计时 | **按住说 / 点击开始**两种都支持,由端决定 |
| 2 录制中 | 计时到 55 秒开始变色,60 秒**自动停止** | 上限 60 秒(`1.1.1.4`) |
| 3 松开 | 立刻进入「已记下」状态 | **先落记录,再转写**——顺序不能反 |
| 4 转写中 | 记录卡片上一行小字「正在转文字」 | 用户可以直接离开这一屏 |
| 5 转写完 | 文本填入卡片,可编辑 | 转写文本**不覆盖**用户已手动改过的内容 |
| 6 转写失败 | 卡片显示「没转成文字,录音还在」+ 重试 | 见 §六 `R-05` |

🔴 **转写完成后服务端不留存音频**(`技术架构与接口契约` §6.2)。界面上要写明这一点:设置里一句「录音转成文字后就不在服务器上了」。

### 3.4 拍照模式

| 步骤 | 界面 | 规则 |
|---|---|---|
| 1 | 相机或相册二选一 | 单次最多 **6 张**(连拍合并,`1.1.2.3`) |
| 2 | 缩略图条,可删除单张 | 超过 6 张时第 7 张的位置显示「最多 6 张」 |
| 3 | 点「记下」 | **先落记录 + 原图存本机**,再上传识别 |
| 4 | 识别中 | 卡片小字「正在认」 |
| 5 | 识别完 | 得到候选考点 → 走 [打标与未分类](打标与未分类.md) |
| 6 | 识别失败 | 「没认出来,图还在」+ 重试 + 手动挂载入口 |

🔴 **原图只存在这台设备上**:界面上没有「上传原图」「备份原图」「同步原图」任何入口,设置里明写这条(见 [设置与原图](设置与原图.md))。

### 3.5 批量补录

| 元素 | 规则 |
|---|---|
| 入口 | `S-REC` 右上角「批量」 |
| 形态 | 多行文本,**一行一条** |
| 上限 | 单批 50 条(`技术架构与接口契约` §6.2);超出时提示「一次最多 50 条,剩下的我给你留着」并**保留剩余文本** |
| 图片 | 批量模式**不带图**——图片逐条走单条流程(base64 内联下 50 条带图会撑爆请求体) |
| 时间 | 整批一个时间,可改 |

## 四、`S-TL` 时间线

| 元素 | 内容 | 为空时 |
|---|---|---|
| 分组 | 按天倒序;每天一个小标题「今天 / 昨天 / 8月30日」 | 「还没有记录」+「记一条」按钮 |
| 每条 | 时间 · 内容摘要(2 行截断)· 来源名 · 标签状态徽标 | 内容为空时显示「(语音)」「(图片)」 |
| 标签状态 | `已对上 {n} 个考点` / `待补` / `没对上` / `正在认` | —— |
| 单条操作 | 左滑:删除;点击:展开详情与手动挂载 | —— |
| 筛选 | 只有两个:**全部 / 没对上的**。没有更多筛选器 | —— |
| 分页 | cursor 无限下拉(`GET /records`) | —— |

**删除一条记录**:浮层确认「删了就没了,和它一起的标签也会删掉」→ `DELETE /records/{id}` → **触发覆盖层重算**。

## 五、每天那两个数字从哪来(阶段 0 判据的落点)

| 数字 | 事件 | 何时 +1 | 何时不算 |
|---|---|---|---|
| **今天记了几条** | `record_created` | 记录落库成功(本机落库也算) | 删除后**不回退历史当天的数**,当天数实时重算 |
| **今天有几次懒得记** | `record_skipped` | 用户点「本来该记,但懒了」 | 没有别的触发方式,**系统不替用户判断** |

⚠️ **这两个数今天仍然是空的**(`总路线图 · 脑图与父子待办` `1.1.4`)。这一份规格写完不会让它们有值 —— **让它们有值的是有人开始用**。

## 七、接口对照

| 动作 | 端点 | 备注 |
|---|---|---|
| 记一条 | `POST /records` | `client_token` 幂等;**记录动作本身永不失败** |
| 语音 | `POST /records/{id}/audio` | ≤60s;转写后不留存音频 |
| 拍照 | `POST /records/{id}/image` | JSON body base64 内联,单次 ≤6 张 |
| 批量 | `POST /records/batch` | 单批 ≤50;只补传文本与元数据 |
| 时间线 | `GET /records` | cursor 分页 |
| 删除 | `DELETE /records/{id}` | 级联删标签,触发覆盖层重算 |

**产品对响应的语义要求:**
1. `POST /records` 必须**先返回成功再做识别**,识别结果异步回来 —— 否则「永不失败」做不到
2. 转写/识别的失败要能区分**额度不足 / 服务故障 / 没认出来**三档,三档文案不同(`R-08` / `R-12`)
3. 批量补传要返回**每条的成功与否**,不能只返回一个整体状态
