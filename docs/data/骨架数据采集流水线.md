# 骨架数据采集流水线 · 后端线设计

> **这份文档回答:被减数(那份考点全集)是怎么被造出来、维护、发布的。**
> 它是**一条纯后端线,没有任何用户界面**,不占 [`用户侧功能规格`](../product/specs/INDEX.md) 里的任何一屏。
> 用户与这条线的接触面只有一个:骨架树 + 每个考点上的四个统计字段。
>
> **不是**抓什么/不抓什么的分级与法律边界(在 [`数据线 · 骨架原料的获取与隔离`](INDEX.md) §二/§三)、
> **不是**源清单与 robots 实测(在 [`基础数据 · 抓取范围与渠道`](基础数据-抓取范围与渠道.md))、
> **不是**识别模型选型(在 [`识别链路选型 · ASR 与图像识别`](识别链路选型.md))。
> 本文只写**流水线本身**:分几段、每段进出什么、失败怎么办、谁按闸。
>
> **基线:`origin/v1` @ `83b9632`,fetch 于 2026-09-01T14:00Z。**
> **状态:活跃。** 段数增删、人工闸位置变化、发布形态变化,本文同一次改动内更新。

## 一、它为什么单独成一条线

用户侧的每一块都要回答「这一屏长什么样」;**这条线一屏都没有**。它的产物是数据,消费者是产品的另一半。

| | 用户侧功能 | 这条线 |
|---|---|---|
| 交付物 | 屏幕与交互 | 一份可发布的考点树 + 统计字段 |
| 验收 | 用户能不能走通 | 数据对不对、来源合不合规、能不能复现 |
| 失败的样子 | 用户看到错误提示 | **没人看见** —— 数据悄悄错了 |
| 节奏 | 跟着阶段走 | 后台常驻,每周工时有硬上限(`数据线 · 骨架原料的获取与隔离` §五) |

**「没人看见」是这条线最需要防的东西。** 所以每一段都要求可复现、留证、可回滚。

## 二、七段流水线

```mermaid
flowchart LR
    S1[① 源清单] --> S2[② 抓取]
    S2 --> S3[③ 解析]
    S3 --> S4[④ 归一]
    S4 --> S5[⑤ 入库为草稿版]
    S5 --> S6[⑥ 人工校正 🚦]
    S6 --> S7[⑦ 发布为正式版]
    S7 -.用户可见.-> U[GET /syllabus/tree]
```

| 段 | 输入 | 输出 | 幂等键 | 失败处理 |
|---|---|---|---|---|
| ① 源清单 | 人工维护的白名单 | 待抓 URL 列表 | 源 ID | 源不可达 → 标记跳过,**不换源** |
| ② 抓取 | URL 列表 | 原始响应 + 抓取时间 + robots 判定留证 | URL + 日期 | 失败重试 3 次后进死信,**不静默丢** |
| ③ 解析 | 原始响应 | 结构化候选:模块 / 题型 / 考点名 | 内容哈希 | 解析不出结构 → 进人工队列,**不猜** |
| ④ 归一 | 候选 | 去重、同义合并、层级归位 | 归一后名称 | 归不进三层树 → **丢弃并计数**,不新建第四层 |
| ⑤ 入库草稿 | 归一结果 | `draft` 版本的树 + 四个统计字段 | 版本号 | 整批事务,**部分成功即整批回滚** |
| ⑥ 人工校正 🚦 | 草稿版 | 校正后的草稿 | —— | **人按闸,不能自动过** |
| ⑦ 发布 | 校正后的草稿 | `published` 版本 | 版本号 | 发布失败 → 保持上一个正式版可用 |

🚦 **⑥ 是这条线上唯一的人工闸,而且它不能自动化。** 理由与 `R-10` 同形:自动化面对模糊数据的本能是「归到最像的那个」,
而这条线的红线正是**宁可丢弃率高,不可准确率低** —— 归错会让覆盖度失真,而覆盖度是这个产品唯一的产出。

## 三、每一段的硬约束

### 3.1 抓取(②)

| 约束 | 说明 |
|---|---|
| robots 判定必须留证 | 每次抓取记下当时的 robots 内容与判定结果 —— **事后说不清就等于没合规** |
| 只抓白名单 | 源清单在 `基础数据 · 抓取范围与渠道`;**D 级源是绝对红线,不碰** |
| 速率 | 按源自带的限制,宁慢不快 |
| 存原始响应多久 | 🚧 见 §六 `D-2` |

### 3.2 解析与归一(③④)

🔴 **这两段是最容易把题干带进来的地方。**

| 约束 | 说明 |
|---|---|
| **只提取考点名称与统计量** | 题干、选项、答案、解析**在解析阶段就丢弃**,不进任何中间表 |
| 中间表结构 | 与正式表同样**没有能装题干的字段**(边界:连预留位都不留) |
| 归一不新建层级 | 三层:模块 → 题型 → 考点,**不做第四层**(`项目现状与决策记录` §2.5) |
| 归不进去的 | **丢弃并计数**;丢弃率进运行报表,不进用户界面 |

### 3.3 统计字段(⑤)

每个考点挂**四个纯统计字段**:近五年出现次数、出现过的省份、最近一次出现年份、平均每套卷题量
(真源 `项目现状与决策记录` §2.5,本文不改一个字)。

| 约束 | 说明 |
|---|---|
| 只有这四个 | 加第五个字段要先改 §2.5,**不在本文加** |
| 都是统计量 | 没有任何一个字段承载学科判断(没有「重要程度」「难度」「推荐指数」) |
| 口径可复现 | 「近五年」的窗口随年份滚动;**滚动的时点要写进版本说明**,否则用户看到的数字会无声变化 |

### 3.4 版本与发布(⑦)

| 约束 | 说明 |
|---|---|
| 正式版不可变 | 发布后的版本只读;改动 = 发新版本 |
| 用户可见的后果 | 树变了、统计数字变了 —— **用户的覆盖度会跟着变,而他什么都没做** |
| 因此 | 版本切换要能回滚;两个版本之间的**考点增删要能列出来** |
| 用户侧文案 | 见 [`看盲区`](../product/specs/看盲区.md) `B-4`:窗口或口径变了,屏幕上的「近 5 年」文案要跟着改 |

## 四、运行形态

| | |
|---|---|
| 触发 | 周期任务(周级),**不做实时** |
| 并发 | 单源串行,多源可并行;速率优先于吞吐 |
| 观测 | 每次运行产出一份运行报表:各段进出条数、丢弃数与丢弃原因分布、死信数 |
| 报警 | 只报**两件事**:抓取连续失败、丢弃率突变。其它一律进报表不打扰人 |
| 回滚 | 保留最近 N 个正式版本(N 🚧 见 §六 `D-3`) |

**运行报表不进用户界面,也不进任何对内指标面板的「进度」位置** ——
它衡量的是数据质量,不是项目进度(`思考模式与选择框架` §盲区二)。

## 五、与产品的唯一接口

| 产品要什么 | 这条线给什么 | 端点 |
|---|---|---|
| 骨架树 + 我的覆盖 | 三层树 + 四个统计字段 | `GET /syllabus/tree`(`技术架构与接口契约` §6.4) |
| 单个考点详情 | 四个统计字段 | `GET /syllabus/nodes/{id}` —— **没有讲解字段** |
| 打标候选集 | 闭集候选,供服务端召回 | `POST /records/{id}/tags/suggest` 内部使用 |

🔴 **自动打标只能从这条线产出的候选集里选一个 `nodeId`,或者返回 `NO_MATCH`。它永不生成标签文本。**

## 六、缺口登记

| # | 缺口 | 卡在哪 |
|---|---|---|
| `D-1` | **谁来按 ⑥ 那道闸** | 现在只有一个人。校正一个科目要多少工时没有实测数,而 `阶段 0 至阶段 2 · 详细排期` §二 的打标工时测算不覆盖这一段 |
