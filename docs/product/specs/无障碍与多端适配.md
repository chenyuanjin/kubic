# 第一部分 · 多端适配

## 一、端的清单与各自定位

**「端」这个词在本文的取口径与 [`多端选型与端矩阵`](../../technical/多端选型与端矩阵.md) §一 完全一致:**
一个形态要成为「端」,判据只有一条 —— 它需要一条自己的构建链或一次自己的分发。光是长得不一样不算。

| 端 | 它是什么 | 当前状态 | 真源指针 |
|---|---|---|---|
| **Web / H5** | 浏览器里打开的那一份,主形态 | ✅ 已在跑(`web/`) | [`多端选型与端矩阵`](../../technical/多端选型与端矩阵.md) §3.1 |
| **桌面壳(macOS)** | Rust + Tauri 2 + WKWebView 包的同一份 `web/dist` | ✅ 实测可装可开(`KUBI-65`) | 同上 §3.3.1 |
| **桌面壳(Windows)** | 与 macOS 同栈同 crate,只差一次平台构建(WebView2) | ⚠️ **未验**,选型已定、排队在 macOS 之后 | 同上 §3.3.2 |
| **移动 App · iOS** | 同一 crate、同一份 dist,Tauri 2 iOS | ✅ 模拟器可开(`KUBI-66`);真机/上架卡在主体决策 | 同上 §3.4 |
| **移动 App · Android** | 同上,Tauri 2 Android | ⚠️ 代码侧已验,环境卡 NDK(`KUBI-67`) | 同上 §3.5 |
| **微信小程序** | 微信原生,手抄 token,**只三屏** | 未开工,阶段 2 后(`执行清单` `L-C` 档) | 同上 §3.6 |
| ~~Pad / iPad~~ | **不是端**,H5 的一组断点 | —— | 同上 §一 / §3.2 |
| ~~桌面(Linux)~~ | **不做**,无触发条件 | —— | 同上 §一 |

**四句必须说清的话:**

1. **桌面壳目前 macOS only。** 没有 `lib` target,所以 **iOS / Android 编不出来**(真源 [`壳技术方案：Tauri 2 包现有 Web 工程`](../../technical/壳技术方案-Tauri2包现有Web工程.md) §2.4、[`多端选型与端矩阵`](../../technical/多端选型与端矩阵.md) §3.3)。**移动端现在能跑的东西只有「模拟器上能打开首页」,没有真机、没有后端接入、没有原图通道。** 本文不假装移动端已经能跑,凡涉及移动端的行为一律按「未验」标注,不按「已跑通」描述。
2. **Windows 与 Linux 是两个不同的词:** Windows 是「未验」(有栈、有顺序、缺一次实测),Linux 是「不做」(无触发条件)。**本文能力矩阵里,桌面壳这一列以 macOS 为准,Windows 在「逐端适配」里单列一节、正文只写「同 macOS,待验」,不写死任何一个 Windows 独有的行为。**
3. **移动 App 的 iOS 与 Android 在「端」这个层面是同一份产物**(同一 crate、同一份 dist),但在**系统事实**层面分叉(安全区、后台限制、存储分区、相册授权模型)。本文在「能力矩阵」里把 iOS / Android 并作一列「移动 App」,在「逐端适配」里**分列 iOS 与 Android**,因为这两处的事实不同。
4. **小程序是唯一一个「原生」端,而且只承接三屏**(采集 · 历史列表 · 设置),其余九屏要么转场网页端、要么根本不存在(真源 [`多端选型与端矩阵`](../../technical/多端选型与端矩阵.md) §3.6.1)。

**「四端」与「六端」的关系,写在这里避免后面打架:** 本文标题里的「四端」是**用户侧视角的粗分**(桌面壳 / 移动 App / Web / 小程序);[`多端选型与端矩阵`](../../technical/多端选型与端矩阵.md) 里的「六个端」是**构建链视角的细分**(Web / 桌面 macOS / 桌面 Windows / iOS / Android / 小程序)。**两者不矛盾:** 桌面壳 = macOS + Windows,移动 App = iOS + Android。本文凡出现「四个端」,指的都是前者。

## 二、十三屏 × 四端能力矩阵

**每一格只有三种取值:** 完整提供 / 降级提供(并说明降什么)/ 不提供(并说明为什么)。
「降级」指功能在、但弱于主形态;「不提供」指该端没有这一屏或这一能力,且**不在该端做一个更弱的同名屏**(真源 [`多端选型与端矩阵`](../../technical/多端选型与端矩阵.md) §4.6.4)。

| 屏 | 桌面壳(macOS/Windows) | 移动 App(iOS/Android) | Web / H5 | 微信小程序 |
|---|---|---|---|---|
| `S-HOME` 首页 | 完整。全局热键 ⌥空格可直接唤起采集屏(`多端选型与端矩阵` §3.3.3) | 完整 | 完整 | **不提供** —— 无独立首页,进入即历史列表(`L-C6` 三屏) |
| `S-REC` 记一次 | 完整。写 / 说 / 拍 | 完整。写 / 说 / 拍 | 完整。写 / 说 / 拍 | **降级** —— 只文字采集 + 录音采集,**不做拍照、不落任何原图字节**(`多端选型与端矩阵` §3.6.1) |
| `S-TL` 时间线 | 完整 | 完整 | 完整 | **降级** —— 即三屏里的「历史列表」;无左滑删除(系统返回手势冲突),删除走长按/按钮 |
| `S-BLIND` 盲区总览 | 完整。桌面多列(左树右详情) | 完整。单列 | 完整。宽屏多列 | **不提供** —— 该屏不在三屏内,转场网页端(`看盲区` §九) |
| `S-NODE` 考点详情 | 完整。右栏 | 完整。独立页面 | 完整。独立页面 | **不提供** —— 同上 |
| `S-TAG` 待补与手动挂载 | 完整。两栏 + 键盘 `1`–`5` 选候选 | 完整。单栏覆盖层 | 完整。宽屏两栏 | **不提供** —— 不在三屏内,转场网页端(见 §十四 冲突 C-4) |
| `S-EXP` 导出与问 AI | 完整。保存对话框落地 | 完整。系统分享面板落地 | 完整。浏览器下载 | **不提供** —— 不在三屏内,历史列表底部一行「导出和问 AI 在网页版和桌面版上」(见 `导出与问AI` §十五) |
| `S-LOGIN` 登录 | 完整。手机号 + 验证码;微信登录不渲染 | 完整。+ App SDK 微信登录 | 完整。微信内 H5 走服务号授权 | **完整(原生)** —— `wx.login` 是原生能力;手机号 + 验证码同样可用 |
| `S-ACC` 账号 | 完整。含设备列表与注销 | 完整 | 完整 | **降级** —— 只做身份与退出,设备列表与注销转网页端(`登录与账号` §十一) |
| `S-MERGE` 合并确认 | 完整 | 完整 | 完整 | **降级** —— 撞号时明确转场网页端,**不做弱化版合并**(`登录与账号` §十一) |
| `S-BILL` 额度与购买 | 完整。支付通道 🚧 待定 | 完整。iOS 走 Apple 内购 | 完整。支付通道 🚧 待定 | **降级** —— 微信虚拟支付;整屏压在备案与资质上(`额度与购买` `Q-3`) |
| `S-SET` 设置 | 完整。全部条目 | 完整 | 完整 | **降级** —— 简化:无「原图管理」条目,「清空」文案不提图(`设置与原图` §10.1) |
| `S-RAW` 原图管理 | 完整。真实文件系统,无配额 | 完整。应用私有目录 | 完整。浏览器本地数据库(弱,见 §五) | **不提供** —— 🔴 该端不开原图通道,整屏不存在(`设置与原图` §10.1) |

**三格之外没有第四格。** 尤其没有「该端显示入口但点了提示去别处」这种半截形态 —— 那会让同一个地址在两个端指向两件事。
**唯一允许的「转场」是:** 小程序端某个 `route id` 不在其子集内时,解析成一句「这一屏在小程序上没有,去网页端」(`多端选型与端矩阵` §4.6.4)。

## 三、逐端详细适配规格

### 3.1 桌面壳(Tauri 2 · macOS)

| 项 | 规格 |
|---|---|
| **窗口尺寸与最小尺寸** | 有窗口;最小尺寸由设计侧定(本文不定视觉),**唯一产品约束是**:窗口缩到最小时,`S-BLIND` 的多列必须退化成单列(见 §四),任何一屏都不许出现横向滚动条 |
| **多窗口** | 🚧 未定 —— 当前无多窗口需求;任何「新开一个窗口放详情」的提议都要先回答「它服务哪个已成立的需求」(`壳技术方案` §四 trait 只有两个方法,加窗口能力等同加方法) |
| **菜单栏** | 🔴 **只留系统最小集,「编辑」必须留** —— 没有它 macOS 部分输入场景 ⌘C/⌘V 失效(`多端选型与端矩阵` §3.3.3)。**不自定义菜单栏**,不往菜单栏塞产品入口 |
| **键盘快捷键** | 全表见 §十一;桌面壳独有的是**全局热键 ⌥空格 记一笔**(唤起已有采集屏,不新增界面,`多端选型与端矩阵` §3.3.3) |
| **拖拽文件** | 🔴 **不提供。** 没有「拖一张图进窗口记一笔」的入口 —— 它绕过「用户同意留存的那一刻」,与「监听截图目录自动入队」被判「否」是同一条边界(`多端选型与端矩阵` §3.3.3) |
| **文件保存对话框** | 导出落地走系统保存对话框,用户自选目录;上次目录记在本机,首次为「下载」(`导出与问AI` §5.4)。🔴 **对话框不是「给原图选目录」的入口**,原图目录用户不可选(`设置与原图` §1.4) |
| **本机存储位置的概念** | 系统给该应用的应用数据目录下的专用文件夹,**不是**文稿 / 桌面 / 图片库(理由见 §五)。界面上**不显示绝对路径、不提供「在访达中显示」** |
| **无摄像头时的降级** | 相机入口**不渲染**(不是灰掉);从相册选与手写照常。区分「没有相机权限」与「这台设备没有相机」两句话(真源 [`首次使用与权限申请`](首次使用与权限申请.md) §2.5) |
| **系统深浅色跟随** | 跟随系统,不给独立开关(`设置与原图` §1.4)。深浅色切换时,§十 每一条「颜色之外的信息载体」的文字不变 |

**Windows 这一格的现状:** 同栈同 crate,§十一 的快捷键、本节的行为在 Windows 上**全部待验**,未验前不在 Windows 上写死任何一条独有行为(真源 [`多端选型与端矩阵`](../../technical/多端选型与端矩阵.md) §3.3.2)。

### 3.2 移动 App · iOS(分列)

| 项 | 规格 |
|---|---|
| **安全区与刘海** | 固定区贴安全区上沿,底部主按钮/底栏落安全区内;`S-HOME` 主按钮「贴安全区上沿」这一条在刘海屏上仍成立 |
| **手势返回** | 系统侧滑返回**优先于**任何应用内左滑手势;左滑热区从条目内侧起(`全局组件与交互模式库` `C-LIST`) |
| **软键盘遮挡** | 遮挡时**整屏上推**,保证当前输入框与它下方的主按钮都可见,不做内部滚动(`总纲` §2.4) |
| **后台被杀与状态恢复** | 🔴 **后台定时器不保证执行。** 到期转留存区这个动作,`background_timer_supported()==false` 时只能**前台启动时扫一次**,且界面上**不承诺任何「到期自动处理」**(真源 `壳技术方案` §五、`多端选型与端矩阵` §五) |
| **系统分享** | 导出落地走系统分享面板;🔴 桌面说「已保存到 {目录}」,移动只能说「导出好了」 —— 说「已保存」而用户点的是「发给微信」,那句话就是假的(`导出与问AI` §5.4) |
| **深链** | `kaodian://<path>` → 壳解析 → 同一个 route id;真上架后加 Universal Links(`多端选型与端矩阵` §4.6.4) |
| **iOS 受限相册访问** | 走 `PHPicker`(无需权限);回落时用 `NSPhotoLibraryUsageDescription`,有「只给部分照片」一档;**受限不是错误态**,给「改选照片」入口,不劝用户给全部(`首次使用与权限申请` §2.6) |

### 3.3 移动 App · Android(分列)

| 项 | 规格 |
|---|---|
| **安全区** | 无刘海安全区概念,但底部主按钮仍要避开系统导航栏 |
| **手势返回** | 系统返回键 = 关闭浮层/选择器,而不是退出屏;物理返回键**不触发**任何按钮(`全局组件与交互模式库` `C-BTN`) |
| **后台被杀与状态恢复** | 同 iOS,后台定时器不保证;前台恢复时重扫一次 |
| **系统分享** | 同 iOS,走系统分享面板 |
| **深链** | App Links(未上架前无) |
| **存储分区** | 原图落**应用私有目录**,别的 App 读不到;🔴 不得落公共外部存储(那会被相册扫描/云同步,等同把原图交出去) |
| **后台限制** | `INTERNET` 是安装期普通权限不弹窗;通知权限 `POST_NOTIFICATIONS` **不声明** —— 不声明就永远不会弹(`首次使用与权限申请` §2.8) |

### 3.4 Web / H5

| 项 | 规格 |
|---|---|
| **URL 与路由** | 全端页面 URL 化,`web/src/routes/routes.ts` 是唯一来源;每屏能否深链见下表(route id 真源 [`多端选型与端矩阵`](../../technical/多端选型与端矩阵.md) §4.6.2) |
| **刷新后的状态保持** | 路由态可恢复(靠 URL 本身);**视图态**(滚动位置、展开态、筛选)按各屏规格记在本机存储,刷新后尽力恢复;恢复不了时回到该屏顶部,**不报错** |
| **浏览器返回键** | 返回键退出当前屏,无「不可返回」的屏;有未保存内容时用浮层问一次(`总纲` §2.4)。`S-LOGIN` 不是路由,按返回键退出门、回到门底下那一屏 |
| **存储的持久性有多弱** | 🔴 **很弱,必须告诉用户。** 见 §五;浏览器可能主动驱逐、用户「清除站点数据」会一起清掉、隐私模式下直接不可用 |
| **HTTPS 才有麦克风/相机** | 非安全上下文没有麦克风/相机能力。桌面壳的回环地址 `http://127.0.0.1:17840` 属可信来源、可用;线上必须是 HTTPS |
| **下载与 Blob 限制** | 导出用 `Blob` + `a[download]`;`Blob` 全量在内存,Safari 没有 File System Access API,超大文件必须分段降级(`导出与问AI` §十五) |
| **剪贴板 API 权限模型** | 必须在用户手势内写;`navigator.clipboard` → `execCommand` → 全选逐级降级(`导出与问AI` §十五)。🔴 **永不主动读剪贴板**,只接受用户自己发起的粘贴 |

**每一屏能不能深链(Web / H5 视角):**

| 屏 | 可深链 | route id | 说明 |
|---|---|---|---|
| `S-BLIND` | ✅ | `coverage` `/coverage` | `/` 重定向到这里 |
| `S-NODE` | ✅ | `coverage.node` `/coverage/:nodeCode` | 深链进入见 `看盲区` §3.5 |
| `S-REC` | ✅ | `capture` `/capture`、`capture.text` / `capture.audio` / `capture.photo` | 采集入口有 URL(浮层由 URL 开) |
| `S-TL` | ✅ | `records` `/records`、`records.detail` `/records/:recordId` | —— |
| `S-EXP` | ✅ | `agent` `/agent`(问 AI)、导出在 `S-SET` 之下 | —— |
| `S-SET` | ✅ | `settings` `/settings`、`settings.privacy` `/settings/privacy` | —— |
| `S-RAW` | ✅ | `archive` `/archive` | 留存区 |
| `S-LOGIN` | ❌ | **`/login` 不存在** | 门是未登录访问任何 route id 时的渲染结果,不是位置(`登录与账号` §1.2) |
| `S-ACC` / `S-MERGE` | ✅ / ❌ | `S-ACC` 有地址;`S-MERGE` 是门不是路由 | —— |

### 3.5 微信小程序

| 项 | 规格 |
|---|---|
| **包体上限对树渲染与长列表的影响** | 小程序端渲染骨架树**不做全树虚拟列表**,只渲染「全部第 1 层 + 当前展开那条路径」,同一时间只能展开一条路径(手风琴)。**这个差异不抹平** —— 抹平会让其他端也退化成手风琴(`打标与未分类` §10.1)。长列表必须用官方虚拟列表方案控制 `setData` |
| **授权 API 与「拒绝后只能去设置页」** | 权限走 `wx.getSetting` 查、`wx.authorize` 申请;🔴 **拒绝后只能 `wx.openSetting`,而它必须由用户点击触发** —— 所以入口永远能点、点下去永远有路(`首次使用与权限申请` §4.2) |
| **文件能力限制** | 本地存储约 10MB,临时文件由微信按自己的策略管理与清理 —— **这正是该端不开原图通道的原因**(`多端选型与端矩阵` §3.6.1) |
| **不提供哪些出口** | 拍照、图片上传、导出文件、问 AI、只读令牌签发、设备列表、注销、盲区/考点/打标三屏 —— 全部转场网页端或不提供 |
| **微信登录在这里是原生能力** | `wx.login` 直接给 code,无跳转;它是三条微信入口之一(小程序 / 服务号 H5 / PC 扫码)里唯一「不整页跳转」的一条(`登录与账号` §3.1) |
| **页面栈层数受限** | 从 `S-NODE` 进 `S-TAG` 这类深层进入时用重定向而非新开页(`打标与未分类` §10) |

## 四、响应式断点与布局规则

**本文不给像素与色板,只给「布局形态的分档」与各屏在各档下的取舍。** 断点的具体数值在 `web/src` 的 Tailwind 断点里(真源 [`多端选型与端矩阵`](../../technical/多端选型与端矩阵.md) §3.2),本文只定「每一档长什么样」。

### 4.1 三档形态

| 档 | 形态 | 谁落在这档 |
|---|---|---|
| **单列** | 全部内容纵向堆叠,无左右分栏 | 移动 App、窄屏 Web、窗口缩到最小的桌面壳 |
| **双列** | 左导航/树 + 右详情 | 桌面壳默认、宽屏 Web、`S-BLIND` 的树+详情 |
| **三列** | 左树 + 中列表 + 右详情 | 🚧 超宽屏预留,当前无屏真用三列;不要为了「对称」硬造第三列 |

**各屏在各档下的取舍(哪块内容优先被折叠):**

| 屏 | 单列 | 双列 | 折叠优先级 |
|---|---|---|---|
| `S-BLIND` | 摘要 → Top N → 出口,全部纵向 | 左树(按章看全部)+ 右 `S-NODE` 详情 | 单列时先折叠「按章看全部」为入口,详情变独立页 |
| `S-NODE` | 独立页,底部固定条三动作纵向 | 桌面壳里是右栏 | 200% 字体时底部三动作改可滚底区 |
| `S-TAG` | 单栏,树选择器全屏覆盖层 | 左记录卡 + 右候选/树,树**不做覆盖层做右栏** | 先折叠候选的章节路径,再折叠「看看丢掉的」 |
| `S-EXP` | 四个区纵向 | 同单列(四个区顺序是产品判断,不分栏) | 回答区区内独立滚动 |
| `S-HOME` | 主按钮 + 三快捷横排 | 同单列 | 三快捷放不下时换两行,**不做横滑** |

### 4.2 三种极端情况的降级

| 极端 | 降级 |
|---|---|
| **横屏**(移动) | 单列照常;`S-REC` 拍照/录音界面允许横屏,文字输入界面不强制横屏;安全区按横屏重算 |
| **平板** | iPad 不是端,是 H5 的断点;中间宽度落在哪个断点**没人验过**(`多端选型与端矩阵` §3.2 ⚪),本文不写死 iPad 独有行为 |
| **桌面窗口缩到最小** | 双列退成单列,**不许出现横向滚动条**;`S-BLIND` 的左栏拖拽调宽到下限后自动切单列 |

**一条不变量贯穿三档:** 任何一屏在任何一档,**折叠线以上必须完整看到的那几样**(各屏规格里写的「折叠线以上」清单)不因分档而少一样。分档改变的是排版,不是信息优先级。

## 五、各端「本机存储」到底是什么(红线落点)

**这一节是「原图只存在他自己的机器上」这条红线在多端上的落点,写到能被检查。**
概念层的真源在 [`原图存储：判据层与存储层`](../../technical/原图存储-判据层与存储层.md) §4.2 与 [`设置与原图`](设置与原图.md) §6.1,本文只把它铺成一张跨端对照表。

| 端 | 存储介质 | 持久性保证 | 用户能不能自己找到 | 被系统清理的可能 | **原图承诺成立吗** | 不成立/弱时界面上怎么说 |
|---|---|---|---|---|---|---|
| 桌面壳(macOS) | 应用数据目录下的专用文件夹(真实文件系统) | ✅ 强;不随浏览器清理、无配额上限 | 能(在系统里找得到),但产品**不带路**(不显示路径、不给「在访达中显示」) | 几乎不发生 | ✅ 成立 | 「这些图在这台电脑上,这个应用自己的文件夹里」 |
| 桌面壳(Windows) | 同栈,待验 | 待验 | —— | 待验 | ✅ 预期成立,待验 | —— |
| 移动 App(iOS/Android) | 应用私有目录 | ✅ 强;别的 App 读不到 | 系统文件 App 里可能可见(iOS),产品不带路 | 🔴 **卸载即随 App 删光** | ✅ 成立,但**换机/卸载不保留** | 「这些图在这台手机上,这个应用自己的地方」 |
| Web / H5 | 浏览器给该 origin 的本地数据库 | 🔴 **弱** —— 见下四条 | 能(开发者工具里),产品不带路 | 🔴 会(磁盘压力驱逐、清站点数据、隐私模式不可用) | ⚠️ **成立但弱** | 见下面 Web 专版文案 |
| 微信小程序 | —— | —— | —— | —— | 🔴 **不成立 → 该端不开原图通道** | 不出现任何原图字样(这句话没有主语) |

**Web 端「弱」的四条,逐条(真源 [`设置与原图`](设置与原图.md) §10.2):**

1. 按 origin 隔离 —— 换浏览器、换配置文件、甚至同一台机器上的壳(回环地址)与网页(线上地址)互相读不到;
2. 浏览器可主动清理 —— 磁盘压力下驱逐非持久化存储,部分浏览器对长期未访问站点有主动驱逐策略;
3. 用户一键清除 —— 「清除浏览数据/站点数据」会一起清掉,而用户不觉得那是在删他的图;
4. 隐私模式不可用 —— 一张都存不下。

**界面上的处置(必须区别于其他端):** Web 端 `S-RAW` 常驻说明用**专版**:

> 「这些图只在这个浏览器里。**换个浏览器看不到,清浏览器数据会一起清掉**,也没有任何地方备份。」

再加一条 Web 独有、可关闭的提示:

> 「浏览器可能在空间不够时清理掉这些图。要它们更稳一点,可以装桌面版。」

🔴 **这句必须点名「浏览器可能清理」,不能只写「建议装桌面版」** —— 后者是推广,前者是告知一个产品控制不了的事实。而且 🔴 **不因为 Web 端弱就在 Web 端加「备份到云」的口子** —— 弱是端的事实,加口子是破红线,两件事不能拿来交换(`设置与原图` §10.2)。

**两条检查:`原图承诺在这个端上成不成立`必须能在这里被查出来:**
- 凡「成立」的端,`S-RAW` 有常驻说明,且没有上传/备份/同步任何入口;
- 凡「不成立」的端(小程序),**没有 `S-RAW` 这一屏,也不出现「原图只存在这台设备」这句话**。

## 六、跨端一致性约定

### 6.1 必须一致的四样(不一致 = 缺陷)

| 维度 | 要求 |
|---|---|
| **文案** | 同一句话不许有两个版本。词表一处定义、各端现读、不抄副本(`多端选型与端矩阵` §4.5)。尤其:错误文案、空态文案、原图常驻说明、禁用原因 |
| **状态** | 同一记录的标签状态、同一订单的界面态、同一屏的四种态,在各端同名同义 |
| **错误表现** | 同一个错误码映射到同一句界面文案(§三 的全局映射);`/api/*` 在任何端返回同一份语义 |
| **数据结果** | 同一条记录、同一个盲区数字、同一份导出文件,**字节级一致**(导出三种格式的字段清单跨端相同,`导出与问AI` §六) |

### 6.2 允许不一致的四样(「允许不一致清单」)

**不在这张清单里的差异,一律算缺陷。**

| # | 允许不一致的维度 | 不一致到哪为止 |
|---|---|---|
| 1 | **交互手法** | 同一动作:桌面用点击 + 键盘,移动用点击 + 手势,Web 用点击。手法可不同,结果与文案必须同 |
| 2 | **布局** | 单列 / 双列 / 三列随端变(§四);信息优先级不变 |
| 3 | **系统级组件** | 保存对话框 / 分享面板 / 浏览器下载 / 系统日期选择器 —— 这些用系统原生的地方,形态随系统 |
| 4 | **系统的「端事实」** | 存储持久性(§五)、后台定时器(桌面真在走 / 移动不保证 / Web 只在打开时走 / 小程序无)—— 这些是端事实,允许如实不同,但**界面必须把「不同」说出来**,不许假装一致 |

**清单之外的差异,举例(都是缺陷):** 桌面壳与 Web 的错误文案不同;小程序的历史列表比 Web 的时间线少了某一行;某端把「没对上」显示成「未匹配」。

**两条跟着这张清单走的硬规矩(真源 [`多端选型与端矩阵`](../../technical/多端选型与端矩阵.md) §五):**

1. 🔴 壳里可以说「到点就处理,不用你打开」,浏览器里**不许**用同一句话 —— 这对用户是变好的,不许为了统一而抹平;
2. 🔴 移动端脚手架阶段,不得出现「能看到但按不动」的承诺 —— 要么屏蔽入口,要么标「脚手架 · 未实现」。

# 第二部分 · 无障碍

## 七、无障碍下限总表

**每一条都给可检查的判据。这些数值是可访问性下限,不是视觉 —— 它们决定「能不能点到、能不能读到、会不会被动画打断」,属于行为。**

| # | 项 | 下限 | 可检查判据 |
|---|---|---|---|
| 1 | **最小点击热区** | 44×44 逻辑像素(pt);列表条目整行是热区 | 任一可点元素的热区(含透明扩展)小于 44×44 → 不合格。缩略图、批量态圆点、文字链(「看看档位」)都算在内 |
| 2 | **文本对比度** | 正文与背景 ≥ 4.5:1;**次要入口不许降到 4.5:1 以下** | 逐屏用取色工具核一遍;「看看档位」按正文标准,不按次要文字标准 |
| 3 | **动态字体放大** | 100%–200%,**不裁字、不缩小字号、不横向溢出** | 系统字号拉到 200%,逐屏看:无截断、无重叠、无横向滚动 |
| 4 | **焦点可见性** | 键盘焦点必须有可见轮廓,不能只靠颜色变化 | `Tab` 走一遍焦点链,每一步焦点清晰可见 |
| 5 | **动画可关闭** | 跟随系统「减弱动态效果」 | 开系统「减弱动态效果」后,门的出现、验证码框滑入、抖动都降级为直接出现/淡入(或直接取消) |
| 6 | **超时可延长** | 不存在「必须在 N 秒内点完否则消失」的不可恢复内容 | 全产品唯一一处「只此一次可见」的内容(令牌明文)🔴 **不做倒计时自动关闭**;其余 Toast 2 秒消失的都不是「不可恢复内容」 |

**200% 字体下的三条跨屏降级顺序(逐屏的细节在各屏「无障碍」节):**
1. 横向多栏 → 纵向单列;
2. 一行多格数字 → 每格独立一行、读成完整句子;
3. 底部固定条 → 动作纵向排,超屏高三分之一改可滚动。

**禁止在 200% 下做的事:** 缩字号、把「7」和「次」分到两行、把令牌明文换行断开、把常驻说明折叠成「展开查看」。

### 7.1 焦点可见性与动画的三条细化

**下限总表第 4、5 条在这里展开成可检查的形态:**

| 项 | 细化要求 | 可检查判据 |
|---|---|---|
| 焦点轮廓 | 键盘焦点必须有可见轮廓;**不靠颜色变化**(颜色变化对色觉障碍用户等于没有) | 桌面壳/Web 上 `Tab` 一遍,每一步都有非颜色方式的焦点指示(轮廓/下划线/形状) |
| 焦点不丢 | 点击后焦点不丢失,留在按钮上或移到结果区;轮询刷新**不夺走焦点、不重建 DOM** | 触发一次异步刷新,焦点不跳走 |
| 焦点陷阱 | 浮层/选择器打开时焦点被困在内,关闭回到触发元素;门(登录/合并)同样 | 打开浮层 Tab 到底再 Tab,焦点回到浮层顶部不跑出去 |
| 动画关闭 | 跟随系统「减弱动态效果」:门的出现、验证码滑入、覆盖层推起、协议抖动全部降级 | 开「减弱动态效果」后,这些动画不再播放或改为无位移淡入 |
| 唯一动效 | 协议未勾选时的抖动是**唯一**主动效,且必须有文字提示陪跑(抖动对读屏用户等于没有) | 抖动发生时同时有页内文字「先勾一下同意协议」 |

**一条不变量:** 无障碍下限是**下限不是加分项**,任何一屏都不允许以「这一屏简单」为由把它简化掉。

| `S-LOGIN` | 关闭 → 手机号 → 清除 → 发送/重发 → 验证码 → 人机验证 → 协议勾选 → 协议链接×2 → 主按钮 → 微信登录 |
| `S-ACC` | 返回 → 身份区 → 绑定区各行 → 设备区各行(每行:设备名 → 退出这台)→ 导出 → 退出登录 → 注销账号 |
| `S-MERGE` | 关闭 → 标题 → 数字区 → 不可逆声明 → 主按钮 → 次按钮 |
| `S-BILL` | 返回 → 刷新 → 档位卡片逐卡 → 支付方式 → 协议 → 支付按钮 → 订单逐行 → 说明 |
| `S-SET` | 返回 → 分组①三条 → 分组② → 分组③ → 分组④ → 页脚(只读) |
| `S-RAW` | 返回 →「选择」→ 计数行(只读)→ 常驻说明(只读,必须被朗读)→ 分组标题 → 缩略图逐格 → 页脚 |

**四条通用规则(所有屏):**
1. 焦点不许跳进不可见区域(折叠的树节点、虚拟滚动窗口外的行不在焦点链里);
2. 浮层打开时焦点锁在浮层内,关闭后回到触发它的元素;
3. 骨架占位不可聚焦,但整个区域朗读一次「正在加载」;
4. 禁用元素**仍然接收焦点**,并把禁用原因朗读出来 —— 跳过去的按钮等于没解释为什么不能点。

### 8.3 朗读文本模板

🔴 **数字必须读成完整句子,不是孤立的「3」。** 核心一句:

> 「你碰过 3 次,最近一次 6 天前」,不是「碰过 3 6 天前」。

| 元素类别 | ❌ 孤立读法 | ✅ 完整句子 |
|---|---|---|
| 首页计数 | 「2 1」 | 「今天记了 2 条,今天有 1 次没记」 |
| 盲区摘要 | 「120 43 77」 | 「这个科目一共 120 个考点,你碰过 43 个,没碰过 77 个」 |
| 盲区列表行 | 「行政处罚的种类 7 没碰过」 | 「行政处罚的种类,近 5 年出现 7 次,你没碰过。双击进入详情」 |
| 树节点 | 「刑法 12/40」 | 「刑法,第 1 层,已展开,这一层里你碰过 12 个考点,一共 40 个」 |
| 金额 | 「¥29」 | 「每月 29 元」 |
| 余量 | 「3/10」 | 「记录识别,本月还剩 3 次,共 10 次」 |
| 次数 | 「碰过 3 次」 | 「碰过三次」,不读「3、次」 |
| 相对时间 | 「34 天前」 | 「三十四天前」 |
| 归档计数 | 「归档 6」 | 「另有 6 个考点已归档,双击查看」 |
| 未分类行 | 「未分类 12」 | 「另有 12 条记录没能对上任何考点,没有算进上面两个数,双击去处理」 |

**另三条通用规则:**
1. 手机号一律按打码形态朗读(「138****8000」),屏幕上不打码但朗读打码;
2. 状态要念出来不靠视觉 —— 留存区角标追加「已在留存区」,标签徽标文字本身就是朗读文本;
3. 🔴 危险操作在朗读文本里就带「不可撤销」,不等浮层才说 —— 读屏用户是在**听列表**,点下去才知道危险就晚了。

### 8.4 逐屏朗读文本细则(补各屏专属规则)

**§8.2 给焦点顺序,§8.3 给通用模板,本节补各屏「这一屏独有」的朗读规则。** 逐屏元素级朗读文本在各自规格的元素清单最后一列,这里只收拢「跨屏要一致、又容易做错」的那些。

| 屏 | 这一屏独有的朗读规则 |
|---|---|
| `S-HOME` | 「今天记了 {n} 条」与「今天有 {m} 次没记」必须**连成一句**读,读成「今天记了 2 条,今天有 1 次没记」;「本来该记但懒了」读成「本来该记但懒了,按钮,点一次计一次」 |
| `S-REC` | 录音按钮按下读「开始录音」,松开读「已记下」;拍照的取景框不朗读内容(内容是视觉的),只读「相机已打开,拍一张然后点记下」 |
| `S-TL` | 记录卡片整卡合读:{时间} + {来源或没写来源} + {标签状态},连成一句;左滑删除在 Web/桌面是行内「删除」按钮,朗读「删除这条记录」 |
| `S-BLIND` | 列表行整行合读,模板 `{考点名},{骨架事实},{我的事实}。双击进入详情`;重算中「我的事实」读「你碰过几次正在重新算」 |
| `S-NODE` | 骨架事实与我的事实**分两段读**,不合成一段(§3.1 的区 2/区 3 是硬分区);「把记录挂到这个考点」读完整考点名 |
| `S-TAG` | 候选读「候选 {i},共 {n} 个:{考点名},位置:{模块} 下的 {题型}」;树的层级靠 `aria-level` 读「第 2 层」,不靠缩进 |
| `S-EXP` | 导出按钮读「导出,不限次数,没有水印」;令牌明文放在 `readonly` 文本框里,可逐字符导航;「复制令牌」有明确 `aria-label` |
| `S-LOGIN` | 手机号按打码形态读;验证码读「验证码,输入框,已填 {n} 位,共 {m} 位」;自动提交前先播「正在登录」 |
| `S-ACC` | 设备行读「{设备名},最近使用 {相对时间},退出这台,按钮」;注销读「注销账号,不可撤销,按钮」 |
| `S-MERGE` | 不可逆声明「合并之后不能拆开」**单独一次播报**,不与数字混读;合并屏数字只读「条数/最早/最近/覆盖度前后值」 |
| `S-BILL` | 档位卡片读「档位,{名称},每月 {金额} 元,包含记录识别 {n} 次、问 AI {n} 次」;推荐/当前档位必须读得出文字标记 |
| `S-SET` | 原图管理读「原图管理,{n} 张,占 {size},按钮」;导出读「导出我的全部数据,不限次数,没有水印,按钮」 |
| `S-RAW` | 常驻说明**必须被朗读,不能设 `aria-hidden`**;缩略图读「{label},{相对时间}的图片」,**不描述图片内容**(那等于把内容搬进替代文本) |

**四条跨屏铁律(违反即缺陷):**
1. 装饰性图标 `aria-hidden`,承载信息的图标必须有文字替代;
2. 错误提示与控件用 `aria-describedby` 程序关联,不只是视觉上放下面;
3. 相对时间读完整(「三十四天前」),绝对时间读完整(「2026 年 8 月 30 日」);
4. 数字与单位不许分行 —— 「7」和「次」必须连在一起读、连在一起排。

## 九、状态变化的播报规则与节流

**读屏器用户看不到徽标/颜色/细条的变化,变化必须播报;但播报不许每秒一次。**

| 状态变化 | 播报时机 | 节流规则 |
|---|---|---|
| **加载中** | 骨架区朗读一次「正在加载」 | 只一次,不进 `aria-live` |
| **成功** | Toast 本身用 `aria-live="polite"` | 一条动作一次;「已记下」「已合并」「已到账」 |
| **错误** | 页内提示 `role=alert`,出现时立即播报 | 不重复播报同一句 |
| **倒计时** | 变化时播报,不逐秒播报 | **每 10 秒播报一次,最后 3 秒不再播报**(用户已在等) |
| **流式返回** | 见下 | 🔴 逐字播报会让读屏器完全不可用 |
| **录音中** | 开始录播「开始录音」,停止播「已记下」 | 录音时长不播报(波形/计时是视觉的,读屏给开始与结束两句即可) |
| **打标状态批量变化** | `aria-live="polite"` | **2 秒窗口内合并成一条**:「{n} 条认完了」,不是每条都播 |
| **删除进度** | `aria-live="polite"` | **每 10% 播一次**,不是每张都播 |
| **同步补传** | 顶部细条 | 补传进度**不播报**(焦点/计数已表达);只在「同步完成」播一次 |

**流式返回(AI 代发)的播报节流(真源 [`导出与问AI`](导出与问AI.md) §17.4):**

| 阶段 | 读屏器行为 |
|---|---|
| 发送后 | 播报「正在等模型回答」,回答区 `aria-busy="true"` |
| 流式中 | 🔴 **不播报增量**,容器 `aria-live="off"` |
| 每收到一个自然段 | 可选「已收到 {n} 段」,**最快 5 秒一次**,不是每段都播 |
| `done` 帧 | `aria-busy="false"`,播报「回答完成,共 {n} 段,按 {快捷键} 从头朗读」 |
| 点「停」 | 播报「已停止,这次没算次数」 |
| 中断/超时 | 播报「回答只收到一半,这次没算次数」 |

🔴 **「从头朗读」必须有** —— 这是读屏器用户读到完整流式回答的唯一路径。
🔴 **「失败不扣额度」要能被听见:** AI 调用失败的错误提示里紧跟一句「这次不算次数」。

## 十、颜色不作为唯一信息载体的逐处落实

**产品里所有靠颜色区分的地方,每一处都要有颜色之外的载体(图标 / 文字 / 位置 / 形状)。**

| 处 | 区分什么 | 颜色之外的载体 |
|---|---|---|
| 盲区列表行 | 碰过 / 没碰过 / 已归档 | 文字「你碰过 {n} 次」/「你没碰过」/「已归档」+ 实心/空心/方框形状(文字是必须,形状是辅助) |
| 打标徽标(十态) | 正在认 / 待确认 / 已确认 / 已丢弃 / 没对上 / 待补 / 手动挂载 / 确认待补传 / 挂载失效 | 每个状态独立文字 + 图形不同(三点脉动/空心圆/实心勾/空心斜杠/空心横线/空心时钟/上行箭头/空心方框) |
| 订单状态 | 待支付 / 支付中 / 到账中 / 已到账 / 已关闭 / 已退款 | 状态文案 + 可选色点 |
| 离线细条 | 离线 / 同步中 | 文字细条本身(「离线中」「正在同步 {n} 条」) |
| 危险操作 | 删除 / 清空 / 注销 | 「不可撤销」文字 + 多一次确认 + 次要色(不靠红色,红色只在浮层确认按钮) |
| 缓存态 | 显示的是旧数据 | 常驻文字「这是刚才的数据」 |
| 重算态 | 数字不可信 | 占位块 + 文字细条「正在重新算」 |
| 排序当前口径 | 当前按什么排 | 「按{口径名}排」这句话本身 |
| 筛选选中项 | 选中了哪一项 | 选中标记 + 朗读「当前选中」 |
| 推荐档位 / 当前档位 | 哪个是推荐 / 哪个是当前的 | 文字标记「推荐」/「这是你当前的档位」 |
| 留存区 / 未挂载 / 损坏 | 原图三种附加态 | 分组标题「留存区」/ 角标图形 /「这张图读不出来了」文字 |
| 禁用条目 | 为什么不能点 | 降低不透明度 + 副标题写明原因,不只是变灰 |

**一条跨屏判据:** 任何一处「去掉颜色就看不出区别」的,都不合格。设计评审与代码评审逐处对照这张表,灰度截图下也要能分开。

## 十二、读屏器与输入法的已知坑

**逐条写现象与规避。** 以下坑多数来自「壳/移动端还没真机验证」的已知风险,以及 Web 端读屏器的通用行为。

| # | 环境 | 现象 | 规避 |
|---|---|---|---|
| 1 | VoiceOver(macOS/iOS) | WebView 内 `aria-live` 比浏览器里更爱整段重读,流式回答会被读成反复的整段 | 流式容器 `aria-live="off"`,只在 done 帧播报(§九);每段「已收到 {n} 段」受 5 秒节流 |
| 2 | VoiceOver | 系统 WebView 里语义元素可能被当成普通文本,按钮角色丢失 | 用语义按钮元素(不是可点 `div`);桌面壳依赖菜单栏「编辑」保留,否则 ⌘C/⌘V 失效 |
| 3 | TalkBack(Android) | 系统 WebView 版本不一,焦点在浮层内外乱跑 | 浮层做焦点陷阱;Android 端未真机验证,§十三 检查清单列为待验项 |
| 4 | NVDA(Windows) | 与 WebView2 的组合未验(Windows 端未构建) | Windows 端 §十一 的快捷键与焦点链全部待验,不写死 |
| 5 | 中文输入法 | 拼音候选窗弹出时触发 `blur`,若此时校验会误报「失焦才校验」 | 桌面壳输入法候选窗弹出**不触发失焦校验**(`全局组件与交互模式库` `C-INPUT`);搜索防抖取「打字停顿」量级,避免拼音未上屏就发请求 |
| 6 | 中文输入法 + 快捷键 | 输入法开启时 `1`–`5` 可能被输入法截获选字 | `S-TAG` 的 `1`–`5`/`D` 在搜索框聚焦时失效;输入法开启状态检测不到时不主动抢键 |
| 7 | 验证码自动填充 | iOS 可从通知栏直填 `one-time-code`,Web 靠 `autocomplete="one-time-code"`;桌面壳没有短信 | 桌面壳无短信 → 无自动填充;移动端优先系统级;不做「产品自己读短信」的任何能力 |
| 8 | 剪贴板 | 部分浏览器 `navigator.clipboard` 需用户手势,小程序 `wx.setClipboardData` 会自己弹「已复制」 | 逐级降级(§3.4);小程序端**不再叠一个 Toast**(微信已提示) |
