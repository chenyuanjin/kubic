## 一、当前结论

**方向:** 面向考试备考人群(公考 + 考研)的跨来源学习记录工具。

**一句话定位:** 你在哪儿学的不重要,重要的是考点覆盖到没有。

**为什么是这个位置:** 这是探索过的所有方向里,唯一一个在位者**结构上不能做**的。粉笔、中公、华图都有自家的错题本和学习记录,但它们只覆盖自家内容,而且**永远不会**去整理竞品的学习记录——聚合等于拆掉自己的围墙。这个激励方向不会改变。

**当前状态:** 有可运行 demo,有完整数据结构设计,**零真实用户反馈**。

## 二、产品定义

### 2.1 三层结构

| 层 | 作用 | 数据性质 |
|---|---|---|
| 骨架层 | 考点全集,差集运算的"减数" | 由公开真题聚类反推,自己维护 |
| 行为层 | 用户实际碰过什么 | 采集所得,产品的真实价值所在 |
| 对话层 | 获客与留存的前门 | 轶事性,不可靠 |

**核心公式:** 盲区 = 骨架层 − 行为层

**对话层不参与这个运算。** 它只负责留住用户,以及给行为层供料。

### 2.2 已定的产品原则

| 原则 | 内容 |
|---|---|
| **能力边界** | 凡需判断"对不对"的一律不做;只做"有没有、几次、多久前" |
| **不做教研** | 不产出学科讲解,学科判断外包给外接模型 |
| **不碰内容** | 不存储任何机构课程内容,只记来源名称与时间 |
| **数据开放** | 用户数据可完整导出(Markdown / CSV / JSON) |
| **接口开放** | 开放 CLI 与 MCP,用户可用豆包、Qwen 等直接读自己的数据 |
| **宁缺毋滥** | 自动打标匹配不上就丢弃,不硬归类——归错会让覆盖度失真 |

### 2.3 采集方式(第一优先级)

**语音、拍照、图文混合是主路径,打字是备选。**

理由:打字在真实学习场景里不可行——正在听课、正在做题、手边是纸笔的时候没人会切出去打字。而录入完整度直接决定诊断质量,这是产品的地基。

| 场景 | 采集方式 |
|---|---|
| 听课中 | 截图课件 |
| 听完一段 | 语音说一句 |
| 做完一套题 | 拍答题卡、拍错题 |
| 纸质笔记 | 拍照 |

**必须画的线:** 图片 OCR 抽取文字和考点标签后,原图只做本地缓存或短期留存,**不做长期云端存储和任何形式的共享**。否则产品会成为盗版课件的托管方。这条第一天不定,后面改不回来。

> ⚠️ **2026-08-29 修正:「短期留存」已改为「本机无限期归档」。**
> 到期行为从**删除**改为**归档保留**(仍然只在本机)。决策人:项目所有者;当时的另一个选项是「保持删除」。
> **本句其余部分一字未改,而且是这次改动特意守住的部分**——不上云、不同步、不共享、不成为托管方。
> 变的只是本机保留时长,没变的是原图**从未离开过这台机器**。
> 落地见 `web/src/lib/rawImageCache.ts` 文件头与 `08` 的 `R-04` / `R-102` / **新增 `R-105`(配额)**。

### 2.4 形态

**响应式 Web 应用为主,移动端为辅。**

原先倾向微信小程序,已推翻。核心场景是 iPad 上边看网课边截图、PC 上复盘导图,小程序在这两个端上体验是残的。微信支付资质是**支付通道**的优势,不应反过来决定产品形态。

### 2.5 考点组织

三层树:模块 → 题型 → 考点。**不做第四层**(用户感知不到,标注准确率撑不住)。

树形相对扁平列表的关键收益:**能表达"整块题型都没碰过"**。扁平网格只能说"漏了两个点",树能说"漏了一整类",后者更接近真实的知识缺口形态。

每个考点必挂四个纯统计字段:近五年出现次数、出现过的省份、最近一次出现年份、平均每套卷题量。

### 2.6 开放策略下卖什么

开放 MCP 之后付费理由必须重新回答。答案是三样:

| 卖什么 | 为什么用户自己做不了 |
|---|---|
| 采集端 | 语音、OCR、自动归类是脏活 |
| 骨架数据 | 考点树、频次统计、考情更新需持续维护 |
| 托管 | 跨设备同步与可靠存储 |

**MCP 开放的是"读",不是"写入和采集"。** 这条线划清楚,开放不会伤到商业模型。

**注意:** MCP/CLI 在考研考公人群里能用的可能不到 1%。**它的真实作用是获得技术社区声量,是营销资产不是收入来源。投入不应超过总精力的两成。**

### 2.7 对外路线图与用户共创(**关卡 2 之后**)

两个对外模块:一份用户看得见的路线图,一个收问题与期望功能的地方。**形态与红线在 `16`。**

三条现在就定死的:

| | |
|---|---|
| **对外路线图 ≠ `08`** | `08` 是对内执行树,含关卡判据与止损线 —— 那些对外读起来是「我们可能随时不干了」 |
| **只展示到下一个关卡,不给日期** | 曾为 GEO 方向写完 12 个月路线图然后整个作废(`02`)。对外路线图会把这个错误请回来 |
| **提案数/投票数不进任何指标面板** | 它们比北极星容易涨。用更容易涨的指标代理更难涨的,等于把指标换掉 |

**`02` 已证伪清单公开化**是这里唯一的增量收益:反馈的回复可以直接指过去,而且内容已经写完了,不需要写代码。

> **时序上必须说清:这两个模块要「已经有用户」才立得住。** 建反馈板 ≠ 获得反馈。
> 关卡 0 的输入是你自己自用两周的两个数字,关卡 2 的输入是 10 个真实用户 —— 都还没发生。

## 三、约束条件

| 约束 | 状态 |
|---|---|
| 竞业协议 | **无** |
| 离职时间 | 一年内 |
| 目标形态 | 2-3 人独立生意,不建销售团队 |
| 面销 | 在职期间不可行(工作日白天 + 身份暴露);离职后再评估 |
| 内容输出 | **已松动**——愿意在抖音/知乎/小红书发文章 |
| 保密与职务成果 | 不用公司非公开材料、设备、上班时间;不挖客户和同事 |

**关于"发文章"的界定:** 能做的是工程记录("我怎么建了一套考研数学考点树"),不是真人出镜、日更、运营人设。这是工具类产品的标准冷启动方式。

## 五、未解决的问题(按重要性)

### 5.1 冷启动的第一千人 —— 唯一贯穿始终的问题

**这是从第一轮到现在,换了四个产品方向都没被解决过的问题。**

愿意发内容是答案的雏形,但**一次都没试过**。Obsidian、flomo 这类产品能靠自传播起来,但起步时都有引爆点——创始人在社区有声量,或赶上某个时机。这一千人从哪来,目前仍是空的。

### 5.2 录入完整度决定诊断质量

"未触达"的判断前提是"学过的都记了"。用户只会记一部分,于是会出现:用户在抖音看了半小时,没记,产品说"你没碰过"→ **他不会认为是自己没记,他会认为工具不准。**

语音+拍照大幅缓解了这一点,但没有根除。"我已掌握"按钮是补丁不是解法。

### 5.3 自驱力用户是最挑剔的一批

笔记工具面向自驱力用户是 segment 定义而非缺陷(Obsidian、flomo、Anki 都如此)。**但这批人已经有 Notion 和 Obsidian,且享受折腾工具本身。** 你不是在填空白,是在抢——手里有他们搭不出来的东西(考点骨架),所以能打,但别低估难度。

### 5.4 考点骨架冷启动是最重的一块

真题收集 → 模型初步聚类 → 人工校正命名 → 逐题打标 → 频次汇总。

**建议只做一个模块起步。** 公考推荐资料分析(题型收敛、考点少、标注准确率高);考研只做公共课(数学/英语/政治大纲公开稳定),专业课让用户自建分支。

**两套骨架同时冷启动,对 2-3 人是灾难。先做一个,验证通过再做第二个。**

### 5.5 待查事项

- 生成式 AI 服务备案要求——**在动手前查清楚,别做完卡在审核**
  > **仍未关闭。** `09` §五 把范围缩小到:调用已备案模型且不微调 → 由地方网信办**登记**而非国家网信办备案,且阶段 0-2 不向公众提供、暂不触发。**但这是推理不是书面确认,必须由律师闭环一次。** 同时查出一条硬义务:上线后须在显著位置公示模型名称与备案号。
- Token 成本控制(长上下文按量计费,重度用户可能吃掉订阅费)
  > **降级为低风险,不删除。** `09` §三 实测:1,000 用户时识别成本约 ¥510/月。**但真正会失控的是重复调用与无上限的 prompt,不是单价**,基线记录照旧。

## 七、决策记录

| 决策 | 结论 | 何时改变 |
|---|---|---|
| 形态 | Web 应用为主,非小程序 | 若验证出移动端才是主场景 |
| 起步模块 | 单模块单科目 | 第一个跑通后 |
| 采集 | 语音/拍照优先 | 若自用两周证明摩擦仍太高 → 整个方向存疑 |
| 教研边界 | 不越线 | 不改变。这条边界是所有优势的来源 |
| 原图留存 | **本机归档保留**(2026-08-29 由「到期删除」改) | 若出现配额问题或合规复核结论相反 |
| 开放程度 | 数据可导出 + MCP 只读 | 不改变 |
| 内容分发 | 工程记录式文章 | 若三个月无效果,重新评估渠道 |
| 面销 | 在职不做 | 离职后重新评估,不要固化成"永远不做" |
| 对外路线图 | 只展示到下一个关卡,不给日期 | 不改变。给日期就是承诺,而下一个关卡过不过还不知道 |
| 用户共创 | 收问题与期望功能;不做评论、投票排序、积分榜 | 有真实用户之后重新评估投票,但**提案数不得进指标面板** |
