# 产品路线图与用户共创

> 两个**对外**的模块:一份用户看得见的路线图,一个收集问题与期望功能的地方。
>
> **这份路线图不是 `08`。** `08-总路线图` 是对内的执行树 —— 三条线、关卡判据、止损线、风险登记册。
> 那些东西不能对用户讲,不是因为要藏,是因为**它们的读者不同、用途不同、更新节奏也不同**(§一)。
>
> **本文只定形态与红线,不排期。** 阶段归属是未决项(§六 `R-94`)——
> 它今天写下来,不等于它现在就该被建出来。

---

## 零、先说清楚这件事的时序

**这两个模块只有在已经有用户之后才立得住。**

`08` §六 描述过一种失败:一条线能产出漂亮的量化进展,**而它不需要面对任何一个真实用户**。
反馈板是这个形态里最像反例、其实最典型的一个 —— 它看上去就是「面对用户」,
但**建一个收集反馈的地方 ≠ 获得反馈**。

| | |
|---|---|
| 关卡 0 的输入 | 你自己自用两周的两个数字(`1.1.4`) |
| 关卡 2 的输入 | 10 个真实用户的行为 |
| 反馈板的输入 | **已经在用这个产品的人** |

前两者都还没发生。所以:**本文写下来是对的,现在把它建出来不是。**

> 判断有没有跑偏,还是那一条:`1.1.4` 那张表有没有在填。

## 一、为什么不能直接把 `08` 发出去

最省事的做法是把 `08` 的待办树公开。**不行,而且理由不是「怕泄密」。**

| | `08` 总路线图(对内) | 本文的对外路线图 |
|---|---|---|
| 读者 | 你自己 | 用户 |
| 内容 | 三条线 · 关卡判据 · 止损线 · 风险登记册 | 已经能用的 / 正在做的 / 在考虑的 |
| 里面有 | **「这个方向可能被砍掉」** | 不含判据,不含止损线 |
| 更新 | 每周 | 关卡通过时 |
| 展开深度 | 只到关卡 2 | **同样只到下一个关卡** |

**第三行是关键。** `08` 里写着「关卡 2 第二个指标不过,第 15 周之后的一切立即作废」。
这句话对内是纪律,对外是**「我们可能随时不干了」** —— 它会让一个正在录入几百条记录的用户
合理地怀疑自己的数据值不值得投入。

> 所以两份不是同一份的两个视图,**是两份文档**。对外那份不从对内那份自动生成。

## 二、对外路线图:只展示到下一个关卡 🔴

**这一条是本文最重要的约束,而它来自这个项目自己的历史。**

`04` 与 `08` 都刻意只细化到下一个关卡,原因写在 `04` 里:
**曾经为 GEO 方向写完 12 个月路线图、成本预算、诊断报告模板和内部操作手册,然后整个作废。**

一份对外路线图会把这个错误重新请回来 —— 因为**用户想看远处**,
而「让用户看到远处」和「承诺远处」在观感上没有区别。

### 2.1 三栏,不是时间轴

| 栏 | 含义 | 能写什么 |
|---|---|---|
| **已经能用** | 现在打开就有 | 具体功能 |
| **正在做** | 当前关卡内的事 | 具体功能 + 大致次序,**不给日期** |
| **在考虑** | 想过,还没决定 | 只写「问题」不写「方案」 |

**没有第四栏。** 不设「未来规划 / 长期愿景」——那一栏的唯一功能是承诺。

### 2.2 三条写法上的硬规矩

| 规矩 | 为什么 |
|---|---|
| **不给日期,一个都不给** | 给了就是承诺。这个产品连自己下一个关卡过不过都不知道 |
| **「在考虑」栏只写问题,不写方案** | 写成方案就变成了预告;写成问题(如「跨科目怎么不互相干扰」)反而能收到有用的回复 |
| **关卡没过就不动这个页面** | 更新节奏跟关卡走。**每周更新一次的路线图会变成一个需要喂养的东西** |

### 2.3 已经做完的事要留在页面上

「已经能用」那一栏**只增不减**。
用户判断一个产品值不值得投入,看的不是它承诺了什么,是**它已经交付过多少次**。

## 三、用户共创:收什么、不收什么

### 3.1 收两类,合并成一条流

| 类型 | 用户实际说的话 | 有用在哪 |
|---|---|---|
| **问题** | 「拍照识别老是认错」 | 直接对应可修的东西 |
| **期望的功能** | 「想要行测其他模块」 | 反映需求分布 |

两类不分区,因为**用户不会先给自己分类**。让他先选类型会劝退一半人。

### 3.2 不做的四样,每样都有具体理由

| 不做 | 理由 |
|---|---|
| **用户之间互相评论** | 一个学习记录工具长出评论区,维护成本与内容风险都来了,而它对北极星指标没有任何贡献 |
| **提案的公开投票排序** | 见 §五。它会创造一个更容易涨的指标 |
| **进度承诺 / 状态标签「计划中」** | 「已读」和「计划中」是两回事,后者是承诺 |
| **积分、徽章、贡献榜** | 它奖励「提交次数」,而这里想要的是**一条说清楚的反馈**,不是十条凑数的 |

### 3.3 必须做的两样

**一、每一条都要有回复,哪怕回复是「不做」。**

不回复的反馈板比没有反馈板更糟 —— 它明确地告诉用户「说了也没用」。

**二、回复要给理由,而理由往往已经写好了。**

见 §四。

## 四、把 `02` 变成产品资产 🔴

**这一节是本文唯一一个「新东西」,其余都是约束。**

`02-已证伪方向与调研结论.md` 记着六个被证伪的方向,每个都有调研数据和死因。
它今天是一份**纯内部文档**。

而反馈板会反复收到指向这些方向的提案 —— 比如「能不能加个选岗功能」「做个题库吧」。
标准回复是「好的我们考虑一下」,**而那是假话**:这些方向不是没考虑,是**考虑过并且已经否掉了**。

所以:**把已证伪清单做成一个公开页面**,反馈的回复可以直接指过去。

| 收益 | 说明 |
|---|---|
| 回复有依据 | 不是「我们不做」,是「我们查过,原因是这些」 |
| 省掉重复对话 | 同一个提案第二次出现时,指过去就行 |
| **它本身是内容** | 一份「我们试过什么、为什么放弃」的清单,比任何功能介绍都更能说明这个产品在想什么 |

**公开时要脱敏的东西:** 涉及具体机构的合规判断、竞业相关的表述、成本与单位经济的数字。
**保留的是:** 方向、调研数据、死因。

> `01` §2.6 说 MCP 的真实作用是**营销资产不是收入来源**。已证伪清单公开化是同一类东西,
> 而且比 MCP 便宜得多 —— **它不需要写代码,内容已经写完了。**

## 五、指标纪律:提案数与投票数不进任何看板 🔴

北极星指标是**主动查看盲区的人数**。

一个共创模块天然会产出三个漂亮的数:提案数、投票数、回复率。
它们的共同点是:**都比北极星容易涨,而且涨了不说明任何事。**

`10` §十 否掉积分/成长体系时给的理由,一字不改地适用于这里:
**用一个更容易涨的指标去代理一个更难涨的指标,是把指标本身换掉。**

| 规矩 | |
|---|---|
| 提案数、投票数**不进**任何对内指标面板 | 它们是运营副产物,不是产品指标 |
| 唯一允许看的共创侧数字 | **「提出问题的人里,有多少是过去 7 天主动查看过盲区的」** |
| 为什么是这个数 | 它把反馈量绑回北极星 —— 一个不看盲区的人提的功能需求,大概率不是这个产品要解决的问题 |
