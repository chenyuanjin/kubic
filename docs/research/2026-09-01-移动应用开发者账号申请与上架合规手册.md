# 移动应用开发者账号申请与上架合规手册

**版本**：2026-09 · **适用范围**：中国大陆 + 海外双线发行的移动应用（iOS / Android / 鸿蒙 / 小程序）

---

## 0. 三十秒速览

| 维度 | 大陆 | 海外 |
|---|---|---|
| 卡点在哪 | **资质**（软著、备案） | **账号**（邓白氏、封闭测试） |
| 账号费用 | 安卓商店全免费 | Apple $99/年 + Google $25 一次性 |
| 最长前置 | 软著 30–60 个工作日 | 邓白氏 1–30 天 |
| 主体要求 | 必须中国大陆主体 | 任意法人实体或个人 |
| 端到端周期 | 2.5–3 个月 | 3–6 周 |

**三条必须记住的红线**

1. 中国大陆 App Store 与国内安卓商店的备案主体，**必须是中国大陆注册主体**。境外公司无法直接完成 ICP 备案。
2. App 名称在软著、ICP 备案、App 备案、各商店上架页必须**逐字一致**。苹果后台已对名称与备案记录做强校验。
3. 2026 年 9 月 30 日起，巴西、印尼、新加坡、泰国的认证 Android 设备将拒绝安装未注册开发者的应用（含侧载）。

---

## 1. 全局地图

发行工作实际上是三条彼此独立的链路，各有各的前置条件，不能互相替代。

| 链路 | 覆盖渠道 | 主体 | 关键前置 |
|---|---|---|---|
| A. 大陆合规链 | 中国区 App Store、华为、小米、OPPO、vivo、应用宝、微信小程序 | 中国大陆公司 | 软著 + ICP 备案 + App 备案 |
| B. 海外发行链 | 全球区 App Store、Google Play | 任意法人实体或个人 | 邓白氏（组织号）或 12 人封闭测试（个人号） |
| C. 鸿蒙原生链 | HarmonyOS 应用市场 | 中国大陆公司 | 独立的 ArkTS/HAP 代码库 + 大陆合规链 |

链路 A 与 C 共用资质但**不共用代码**；链路 A 与 B 共用代码但**不共用合规材料**。做预算和排期时按这个切分。

## 2. 主体决策（最先要拍板的事）

### 2.1 大陆主体形态对比

| 主体 | 可用渠道 | 主要限制 |
|---|---|---|
| 有限公司 | 全渠道无死角 | 需注册地址、对公账户、法人身份 |
| 个体工商户 | 应用宝、华为、小程序 | 微信认证费限时优惠 300 → 30 元；单一身份证最多注册 5 个小程序；主体名称必须带"（个体工商户）"后缀，差一字符即驳回 |
| 个人 | 应用宝、华为（vivo/OPPO/小米基本只收企业） | **只能备案非经营性工具类 App**；一旦涉及收费、会员、广告即属经营性，必须企业主体 |

**结论**：任何有商业化计划的产品，直接注册有限公司。个体户和个人主体在收费的那一刻就要推倒重来，且备案主体变更等于全部重做。

### 2.2 一个 App、一个 Apple 账号的约束

一个 App 只能挂在一个 Apple 开发者账号下，而中国大陆上架要求 App Store Connect 的主体信息与 ICP 备案主体一致。因此主体方案只有三种：

| 方案 | 优点 | 代价 | 适用 |
|---|---|---|---|
| 大陆公司做唯一 Apple 主体 | 中国区通畅，全球区一并覆盖，只交一份年费 | 收款走中国实体，涉及税务与外汇结算 | 用户主体在大陆 |
| 境外公司做唯一主体 | 海外收款干净，税务简单 | **中国区备案走不通**，等于放弃大陆 iOS | 用户主体在海外 |
| 两个账号、两个 App | 两边都干净 | 用户数据割裂、双份维护、ASO 从零重来 | 两个市场产品形态本就不同 |

用户在哪个市场，就用哪个市场的主体注册 Apple 账号——这是唯一不会后悔的判断标准。

### 2.3 邓白氏编码（D-U-N-S）

一个编码同时供 Apple 组织号、Google 组织号、华为海外企业号使用，**建议在营业执照下来当天就发起申请**，因为它同时卡住海外两个平台，且不依赖任何其他材料。

| 项目 | 说明 |
|---|---|
| 费用 | 通过 Apple / Google 的专用通道申请免费 |
| 周期 | 专用通道标准 1–5 个工作日；走普通商业通道可能拖到 28–30 天 |
| 前提 | 必须是法人实体（有限责任公司、股份公司、有限合伙等）。DBA、商号、分公司不被接受；独资/单人企业只能按个人身份注册 |
| 高频问题 | 若 D&B 库中已存在你公司的记录但法律状态标为"个体经营"或未核验，需备好营业执照原件邮件联系 D&B 更正 |
| 警告 | 不要购买第三方"加急"服务 |

# 第一部分：大陆篇

## 3. 三张通行证

这三样是所有大陆渠道的共同前置，**只能串行不能跳**。

| 资质 | 办理方 | 周期 | 作用 |
|---|---|---|---|
| 软件著作权 | 中国版权保护中心 | 30–60 个工作日，可加急 | 证明知识产权归属，安卓各大商店的硬性前提 |
| ICP 备案 | 云服务商代备案（阿里云 / 腾讯云等） | 管局一般 20 个工作日内 | 域名合规，未备案域名无法通过商店核验 |
| APP 备案 | 全国互联网移动应用程序备案管理系统 | 平台初审 1–2 个工作日 + 管局约 20 个工作日 | 上架应用市场的法定前提 |

### 3.1 办理顺序

1. 营业执照下证
2. 购买域名 + 大陆云服务器（备案要求服务器在大陆）
3. 提交 ICP 备案 → 取得备案号
4. ICP 通过后，在移动应用备案系统提交 APP 备案 → 取得 App 备案编号
5. 软著与第 2–4 步**完全并行**，第一天就启动
6. 备案编号需在 App 设置页与隐私政策显著位置公示

### 3.2 名称一致性登记表（建议实际填写并存档）

| 字段 | 值 | 状态 |
|---|---|---|
| 软著登记名称 | | |
| ICP 备案主体名称 | | |
| APP 备案名称 | | |
| App Store Connect 显示名 | | |
| 安卓各商店应用名 | | |
| 小程序名称 | | |
| 域名 | | |
| 包名 / Bundle ID | | |

**规则**：同一主体下同一 App 在不同渠道若用了不同名称（且安装后名称也不同），需按不同 App 分别备案，会产生多个备案号。带后缀的版本（如"极速版"）算独立 App。

### 3.3 单机应用例外

若 App 在完全无网络环境下所有核心功能仍能正常使用，属单机应用，部分平台允许在"备案信息"处勾选"单机 APP"免于备案。含云同步、账号体系、AI 调用的产品不适用此例外。

## 4. 中国区 App Store

账号与海外共用同一个 Apple Developer Program 会员（详见第 8 节），差别仅在中国大陆上架环节。

| 环节 | 要求 |
|---|---|
| 年费 | $99，中国区显示为 688 元 |
| 上架前提 | 填写有效 ICP 备案号 |
| 校验 | 后台自动核验 App 名称是否与工信部记录一致，不符则无法保存、无法进入下一步 |
| 存量应用 | 已在架应用做版本更新时通常不强制校验，但存在"备案号不一致"被抽查的案例 |
| 特殊品类 | 新闻、游戏、图书等还需额外许可证 |

**常见错误提示对照**

| 提示 | 真实原因 |
|---|---|
| 无法在中国工业和信息化部识别提供商名称 | App Store Connect 的主体名称与备案主体不一致 |
| ICP 备案号与 MIIT 记录不符 | 备案号填错，或备案刚通过尚未同步（等 1 个工作日重试） |
| 缺少 ICP 备案号 | 中国大陆上架开关已打开但备案字段为空 |

## 5. 华为：两条独立赛道

这是最容易被低估的成本项。

| | 华为应用市场（Android） | HarmonyOS 应用市场 |
|---|---|---|
| 包格式 | APK | HAP |
| 开发语言/工具 | 原有 Android 技术栈 | ArkTS + DevEco Studio |
| 是否需重写 | 否 | **是，等于第二套代码库** |
| 背景 | 兼容老设备 | HarmonyOS NEXT 起底座全线自研、移除 AOSP 代码，直接打开 APK 会提示"无法打开此文件" |

**建议**：小团队第一年只做 APK 版本，观察目标人群中鸿蒙设备的实际占比后再决定是否投入原生开发。不要在产品尚未验证需求时开第二条代码线。

### 5.1 华为企业实名认证

三种方式可选，官方推荐第一种：

| 方式 | 说明 |
|---|---|
| 企业对公账户打款认证 | 操作最简单、周期最短，**首选** |
| 企业资料人工审核认证 | 无对公账户时使用，周期较长 |
| 华为云授权认证 | 已有华为云企业实名的可直接授权 |

### 5.2 华为上架高频驳回点

| 问题 | 应对 |
|---|---|
| 备案类型选错 | 大陆开发者服务器必须在大陆，选"APP 服务器在中国大陆"并完成备案 |
| 主体信息错位 | 上架时录入的必须是**备案主体**信息，而非公司别名或品牌名 |
| 系统延迟 | 备案刚通过时等待 1 个工作日再提交，避免数据同步延迟导致校验失败 |
| 三方登录 | 支持非自有账号体系登录的，需按平台要求额外说明 |

## 6. 小米 / OPPO / vivo / 应用宝

五大渠道合计占国内约 90% 以上的分发量。

### 6.1 通用要求

| 项目 | 说明 |
|---|---|
| 费用 | 注册与认证**均免费，无年费** |
| 企业认证 | 营业执照 + 法人身份证 + 对公账户打款核验 |
| 个人认证 | 身份证 + 人脸识别 |
| 不可逆 | 个人 / 企业类型**注册后不可更改**（小米等平台明确） |
| 资质核验 | 1–2 个工作日 |
| 应用审核 | 1–3 个工作日 |
| 主体口径 | vivo、OPPO、小米基本只接受企业；应用宝、华为支持个人（以平台当期公告为准） |

### 6.2 包体规范

| 项目 | 要求 |
|---|---|
| 格式 | 优先 AAB，兼容 APK |
| 包名 | 全渠道唯一且一致 |
| 版本号 | 规范三段式 |
| 签名 | 必须正式签名文件，**不可使用测试签名** |

### 6.3 平台差异速查

| 平台 | 需特别注意 |
|---|---|
| 小米 | 应用名 15 字上限 |
| OPPO | 应用名 15 字上限；需提前备好软著 |
| vivo | 敏感权限必须逐条写权限说明并上传对应功能截图 |
| 应用宝 | 不支持 API 首次发布，只能后台手动操作；对启动速度与崩溃率有硬性指标 |
| 通用 | 隐私政策网址必须与 App 内展示的完全一致；应用截图须与实际内容相符，不得出现其他品牌标识 |

### 6.4 素材准备清单（一次备齐，全渠道复用）

- [ ] 应用图标（多尺寸）
- [ ] 应用截图两套（16:9 与 18:9）
- [ ] 应用名称（≤15 字）
- [ ] 一句话简介 / 长描述
- [ ] 隐私政策 URL（与 App 内一致）
- [ ] 敏感权限说明 + 对应功能截图
- [ ] 测试账号与密码（含登录功能时必备）
- [ ] 软著证书扫描件
- [ ] ICP 备案证明 + App 备案编号
- [ ] 营业执照扫描件

## 7. 微信小程序

链路最短，适合作为需求验证的第一站。

| 步骤 | 细节 |
|---|---|
| 1. 注册 | 在微信公众平台选择"小程序"→前往注册 |
| 2. 主体验证 | 二选一：对公账户小额打款（**须在 10 天内完成汇款，逾期注册失败**）或微信认证 300 元 |
| 3. 微信认证 | 1–5 个工作日；认证完成前部分功能不可用；申请微信支付必须先认证 |
| 4. 名称 | 认证成功后重置 2 次改名机会，备案被驳回改名要用这个额度，不要浪费 |
| 5. 备案 | 前置条件是小程序已通过认证；小程序自 2023-09-01 起须备案后才可上架 |

**备案五环节**：信息填写 → 平台初审 → 工信部短信核验 → 通管局审核 → 备案成功

**备案材料**

- [ ] 营业执照
- [ ] 通讯地址
- [ ] 主体负责人身份证、手机号、邮箱
- [ ] 小程序类目与业务描述
- [ ] 小程序负责人身份证、手机号、邮箱
- [ ] 小程序负责人授权书（负责人与主体负责人非同一人时，需按官方模板打印并盖公章）
- [ ] 前置审批承诺书（官方模板，盖公章）

备案通过后无需手工添加备案信息，平台会自动写入小程序简介。广东省地区需打印资料签字盖章后上传。

## 8. 大陆费用与周期总表

| 项目 | 费用 | 周期 | 可否并行 |
|---|---|---|---|
| 有限公司注册 | 视代办与地址 | 1–2 周 | 起点 |
| 软著 | 免费（加急另计） | 30–60 工作日 | ✅ 全程并行 |
| 域名 + 大陆服务器 | 按用量 | 即时 | ✅ |
| ICP 备案 | 免费 | 约 20 工作日 | 依赖域名 |
| APP 备案 | 免费 | 约 20 工作日 | 依赖 ICP |
| 微信认证 | 300 元（个体户 30 元） | 1–5 工作日 | ✅ |
| 小程序备案 | 免费 | 约 2–3 周 | 依赖微信认证 |
| 五大安卓商店账号 | **全免费** | 1–2 工作日 | ✅ |
| 中国区 App Store | 含在年费内 | — | 依赖 App 备案 |

**关键路径**：软著（30–60 工作日）与 ICP→App 备案（约 40 工作日串行）是两条并行的长链，端到端约 **2.5–3 个月**，且无法压缩。

# 第二部分：海外篇

## 9. Apple Developer Program

### 9.1 三种会员对比

| | 个人 | 组织 | 企业版 |
|---|---|---|---|
| 年费 | $99 | $99 | $299 |
| App Store 上架 | 可 | 可 | **不可**（仅内部分发） |
| 商店显示名 | 开发者真实姓名 | 公司法定名称 | — |
| 邓白氏 | 不需要 | 必需 | 必需 |
| 付费顺序 | 先付费，后审核 | 先审核，后付费 | 先审核 |
| 团队协作 | 不支持 | 支持角色分配 | 支持 |
| 类型变更 | 转组织需重走流程，繁琐 | — | — |

**选型**：计划上架 App Store 的，只能在个人与组织之间选，**企业版没有上架权限，不要混淆"公司账号"与"企业账号"**。

### 9.2 个人账号办理步骤

1. 创建 Apple 账号并开启双重认证
2. 准备一台带 Touch ID / Face ID 的 iPhone 或 iPad，或带 T2 芯片 / Apple 芯片的 Mac——**全程必须使用同一台设备**
3. 在 Apple Developer App 中开始注册，填写法定姓名与电话（不可填昵称、简称或公司名，否则会延误审核）
4. 拍摄护照或政府签发的带照片证件完成身份验证
5. 同意开发者协议，订阅年费
6. 自动续费默认开启，建议保持开启（漏续费的恢复流程很麻烦）

### 9.3 组织账号办理步骤

1. **先备齐材料**（见下表），特别是邓白氏，最耗时
2. 用公司域名邮箱创建专用 Apple 账号并开启双重认证
3. 网页端进入注册流程，实体类型选"组织"
4. 填写法定名称、邓白氏编码、总部地址、电话、官网
5. 若非创始人或法人，提供可确认你具备签约权的推荐人
6. 等待苹果审核，通常两周内会有电话核实
7. 审核通过后再付费激活

**组织账号材料清单**

- [ ] 法人实体资格（不接受 DBA、商号、分公司；独资/单人企业按个人注册）
- [ ] 九位邓白氏编码，且法定名称与 D&B 记录**逐字符一致**（标点、Ltd./Limited 缩写均计）
- [ ] 公司域名邮箱（个人邮箱不被接受）
- [ ] 可公开访问的公司官网，域名归属公司，内容不得只有"建设中"或社交主页跳转
- [ ] 申请人具备约束公司的签约权：法人、创始人、高管、资深项目负责人，或经高管书面授权的员工
- [ ] 部分地区可能要求提供经公证的公司文件

### 9.4 高频驳回原因

| 原因 | 修复动作 |
|---|---|
| 法定名称与邓白氏记录不一致 | 去 D&B 核对存档名称，一字不差地更新注册信息 |
| 邓白氏记录中的电话打不通 | 在 D&B 更新为有人接听的号码，并提前通知接线人 |
| 官网无法访问或与公司无关 | 上线可公开访问的官网后再提交 |
| 使用了个人邮箱 | 改用公司域名邮箱重新提交 |
| 付款被拒 | 更换支付方式，确认账单地址与银行登记一致 |

## 10. Google Play Console

### 10.1 两种账号对比

| | 个人 | 组织 |
|---|---|---|
| 费用 | $25 一次性，无年费 | $25 一次性 |
| 材料 | 政府身份证件 + 付款卡 | 身份证件 + 邓白氏 + 营业执照/税务登记 |
| 公开信息 | 姓名、地址、国家全部公开 | 公司名称 |
| 12 人 × 14 天封闭测试 | **必须完成** | **豁免** |
| 身份审核 | 几小时至 2 个工作日 | 2–5 个工作日 |
| 类型变更 | **注册后不可更改** | — |

### 10.2 封闭测试规则（注意网上大量教程已过时）

- 要求为 **12 名测试员连续 opt-in 满 14 天**。该数字 2024-12-11 由 20 降至 12，仍在引用 20 人的资料均已过时。
- 仅适用于 **2023-11-13 之后创建的个人账号**。
- 计的是**连续 opt-in 状态**：掉到 11 人时钟从头开始。实操建议招募 15–18 人做缓冲。
- 12 人只是最低门槛。申请生产权限时需回答测试员如何参与、给出了什么反馈，参与度不足会被要求继续测试。
- 测试员本人可跨 App 复用，但 opt-in 状态不能继承，每个新 App 各自计时。
- 达标前，Console 的"正式版"与"预注册"等功能保持禁用。
- 应用必须处于可用状态。启动即崩溃、核心功能不可用会被判定为非真实测试。上线封闭测试前先在 2–3 台真机做内部测试。

### 10.3 组织账号办理步骤

1. Google 账号开启两步验证
2. 申请邓白氏（与 Apple 共用同一个）
3. 支付 $25 注册费
4. 选择"组织"类型，填写与注册文件**完全一致**的法定名称（不用商号、简称、DBA）
5. 上传营业执照 / 公司注册证书 / 税务登记
6. 等待身份验证（2–5 个工作日）；验证期间可上传构建包和商店listing，但不能发布到任何轨道
7. 验证通过后直接申请生产权限，无需封闭测试

### 10.4 分成

每位开发者每年前 100 万美元订阅收入抽成 15%，超出部分 30%。

## 11. ⚠️ Android 开发者验证新规（时间敏感）

这是 2026 年 Android 分发最大的变化，**影响范围远超 Google Play**。

### 11.1 时间表

| 时间 | 事件 |
|---|---|
| 2026-03-30 | 验证流程向所有开发者开放（Play Console 与新的 Android Developer Console） |
| 2026-04 | Android Developer Verifier 系统服务出现在设备的 Google 系统服务设置中 |
| 2026-08 | 有限分发账号与"高级流程"侧载全球上线 |
| **2026-09-30** | **巴西、印尼、新加坡、泰国**：未注册应用无法在认证 Android 设备上正常安装或更新 |
| 2027 | 验证要求推向全球 |

### 11.2 首批覆盖的商店

Google Play、三星 Galaxy Store、小米 GetApps、荣耀应用市场、OPPO 应用市场、vivo 应用商店、Palm Store。

注意其中包含四家国产厂商的**海外**商店——这意味着即使不走 Google Play，只要目标是这四国用户，同样受约束。

### 11.3 三种应对路径

| 场景 | 做法 |
|---|---|
| 只走 Google Play | 已在 Play Console 完成验证的，状态自动延续，基本无额外工作 |
| 站外分发（官网 APK、直接发包给用户） | 在 **Android Developer Console** 单独注册包名；建议把所有 form factor 都注册上以免后续补 |
| 早期小范围试用 | **有限分发账号**：免注册费、无需提供政府身份证件、可分发至最多 20 台设备，适合学生、爱好者与种子用户测试 |

未注册应用仍可通过 adb 或"高级流程"侧载，但普通用户无法完成，不能作为分发方案。

## 17. 沟通话术模板

### 17.1 邓白氏申请 / 催办邮件

> 主题：D-U-N-S Number Request for Apple Developer Program Enrollment — [公司法定全称]
>
> 正文要点：
> - 说明用途：申请编码用于 Apple Developer Program / Google Play Console 注册
> - 提供公司法定全称（与营业执照完全一致）、注册地址、成立日期、统一社会信用代码、官网、联系电话与邮箱
> - 附营业执照扫描件
> - 明确询问预计出号时间，并请求在记录中确认法律实体状态为有限责任公司而非个体经营

### 17.2 苹果核实电话接听要点

苹果通常在提交后两周内致电，用英文或当地语言核实。接线人需能回答：

| 提问 | 应答要点 |
|---|---|
| 公司名称 | 报出**法定全称**，与提交信息完全一致 |
| 申请人姓名与职务 | 与注册表单中的账户持有人一致 |
| 申请人是否有权代表公司签署协议 | 明确回答"是"，并说明职务 |
| 公司地址 | 与邓白氏记录一致的总部地址 |
| 是否知晓此次 Apple Developer Program 申请 | 明确知晓 |

**准备动作**：提前把上述五项写在一张纸上贴在前台/接线人工位，并告知近两周会有 Apple 来电。

### 17.3 商店审核驳回申诉

> 结构：确认问题 → 说明已做的修改 → 提供验证方式 → 请求复审
>
> 示例框架：
> - 感谢审核反馈，我们已确认问题为 [具体项]
> - 已在 [版本号] 中完成以下修改：[逐条列出]
> - 相关佐证：备案号 / 软著登记号 / 截图 / 测试账号与密码
> - 恳请安排复审，如仍有疑问可通过 [联系方式] 与我们沟通

避免：情绪化表述、笼统的"已修复"、要求加急。

### 17.4 Google Play 封闭测试员招募

> 招募文案要点：
> - 说明这是一个真实产品的早期测试，不是刷量
> - 明确要求：需在 14 天内保持加入状态，期间实际打开使用几次
> - 说明会请对方给出简短反馈（Google 申请生产权限时会问）
> - 提供加入链接与操作步骤截图
> - 说明测试期结束后的回报（早期权益/会员等）

**执行提醒**：招 15–18 人而非刚好 12 人；从第 1 天起就在 Console 观察参与数据，发现"零活跃"的立刻替换，不要等到第 13 天。

### 17.5 云服务商备案客服沟通要点

- 明确说明是"App 备案"还是"ICP 备案"，两者流程不同
- 提前确认所在省管局的特殊要求（如广东需打印盖章）
- 询问是否涉及前置审批（教育、医疗、金融等类目）
- 确认 App 名称是否与软著、商店名称一致，避免走完流程才发现要改名
