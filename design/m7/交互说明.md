# M7 交互说明（商业化与额度）

来源：`KUBI-87` 交付评论（comment `01a06d32-ad9b-7aee-b85d-28484fc650b1`，2026-09-04，工程 `kubi-87-m7-v10`）+ 该议题 description。本文只搬运登记，不新增设计。
底座：`tokens.css` + `v10.css`，一字未改。展示字宋体（Songti SC），正文苹方（PingFang SC），全部经底座 token，无新增色值。
骨架：每屏都是 状态细条 → 单栏内容流 → 屏底动作区。没有任何导航侧栏与路径条，列表唯一形态是台账行（宋体序号 + 两行事实，无表头无斑马纹）；屏底动作区的主按钮在商业化全部五屏里都留给免费路径（手动挂考点 / 回去看盲区 / 先去看盲区），付费动作只以次按钮与文本链存在。
蓝面 0 块：蓝面恒定含义是「你还没碰过的那部分」，额度语境不匹配，宁缺勿错。
屏清单：交付评论的 6 张稿与本目录 6 个 html 一一对应，无多无少。
交付评论另有一段 grep 自查真实输出（禁用词 / 站外引导 / 新色值 / 进度环均为 0），其中命令行含边界词表原文，本文不转引，见原评论。

## 逐屏：触发 → 反馈 → 失败落点

### 受限态（U7.1 位置一 / U7.2）· `limited.html`

| | |
|---|---|
| 触发 | 拍照识别撞额度：记录卡片先存在（已存下·待补，TS-06），受限态嵌其下 |
| 反馈 | 「这个月的 AI 次数用完了(还剩 0 次)」+ 唯一按钮控件=屏底「手动挂考点」（免费兜底，焦点第一站）；「看看档位」是 14px 文本链、非主色、字号小于正文 |
| 失败落点 | 记录成功与额度耗尽同屏可见——额度没有挡住记录；这一条不打标、进未分类，记录照样成功 |

### 额度与购买（U7.1 位置三 / U7.3 / U7.7）· `buy.html`

| | |
|---|---|
| 触发 | 额度呈现位置三进入购买屏 |
| 反馈 | 五区单列到底：区一余额（两行「还剩 n 次」+ 每月 1 号重置 + 刷新；免费档到期行不渲染）→ 区二档位（服务端数组渲染，已选=上缘墨线+文字「已选」，日均行是唯一缓解，无划线价）→ 区三支付方式（Apple 内购是首发通道；非 iOS 通道是同一区三的通道行数组多一行，◉/○ 单选行复用同一形态；「恢复购买」在区三支付方式行右侧，次级文本按钮，恰好 1 处/屏）→ 区四订单 + 全部订单 → 区五说明永不折叠（三句承诺全在首屏内）。无横向 Tab、无分步向导、无底部悬浮购买条 |
| 失败落点 | 恢复购买接续未完成事务时就地一行「上一笔还没走完,正在接着处理」（P-52），权益只到账一次；余量表达全部是「还剩 n 次」数字陈述，无进度条/百分比/环 |

### 确认页（U7.4 / U7.7）· `confirm.html`

| | |
|---|---|
| 触发 | 购买屏选定档位后进入确认页 |
| 反馈 | 档位·价格·两类次数 → 通道 → 退款说明格（U7.7：只留格，裁定前一个字不写）→ 协议默认不勾 → 去支付 |
| 失败落点 | 返回任何时候可用，退回不弹挽留 |

### 支付「慢了」态（U7.4 / U7.6）· `paystate.html`

| | |
|---|---|
| 触发 | 轮询到上限（是「慢了」，不是失败） |
| 反馈 | 「钱已经付了,到账慢了一点」，不倒计时不显秒数；主=先去看盲区，次=再查一次 |
| 失败落点 | 这一格永远没有「重新支付」 |

### 订单历史（U7.6）· `orders.html`

| | |
|---|---|
| 触发 | 购买屏子页（区四「全部订单」进入） |
| 反馈 | 台账行四类信息（商品名·金额·状态·时间），倒序；六个状态各一行——正在到账 / 钱收到了,权益还在处理（独立一态，与「正在到账」两句不同的话）/ 待支付可接着付 / 已到账 / 超时关闭没有扣款 / 已退款（无发起退款入口）。底部「没有更多」，游标自动加载无页码 |
| 失败落点 | 超时关闭没有扣款；待支付可接着付；已退款无发起退款入口 |

### 核心屏 iPad 档（U7.3）· `buy-ipad.html`

| | |
|---|---|
| 触发 | iPad 竖屏（834×1194，落在 720–1023 档）打开购买屏 |
| 反馈 | 只放宽——左边线 24→32px，内容 640px 居中，不引侧栏，信息顺序与 iPhone 完全一致 |
| 失败落点 | 同 `buy.html`，无本档独有失败态 |

留白照规格：退款说明格空着（U7.7 当前规格）、联系方式链指空（上游未定）、开票只画入口不画抬头输入。iOS 价格差异只有一行事实小字「这个价格是这台设备上的价格」，不写原因。

## 它服务于哪个关卡

（搬自议题 description）**额度不能挡住记录。** 付费是次要目标：挡住记录，就是亲手把唯一那个数做低。这个模块的成功首先体现为它**没有伤害**别的模块。

## 成功的可观测信号

（搬自议题 description）**额度受限态下记录成功率仍是 100%**（第一位）；受限提示 → 购买屏的转化（第二位）。
