# 思考模式与选择框架

> **先说一句反对的话,它比框架本身重要:**
> 这次讨论里真正让事情前进的,从来不是框架,是四次调研和五次纠正。
> 框架能防止重复犯已犯过的错,**不能帮你发现新东西**。
> 而写完框架最大的风险是——它会让人产生"我又想清楚了一层"的满足感,从而继续推迟去问真实用户。

---

## 第一部分:选择框架

### 顺序不能换

**方向 → 能力如何嵌入 → 具体产品**

这次讨论前期把这三步做反了:从能力出发倒推方向。结果是连续四个方向被证伪。

### 第一步:选的不是"行业",是"位置"

**同一个行业里有好位置也有死位置。** 公考行业里,选岗是死位置(巨头免费),跨机构记录是好位置(在位者不能做)。

三个问题,顺序不能换:

| 顺序 | 问题 | 不过就淘汰 |
|---|---|---|
| 1 | 谁在这儿?为什么他们没做好? | 有巨头免费做 → 死 |
| 2 | 这个位置会不会被大公司顺手做掉? | 会 → 死 |
| 3 | 我能不能持续、低成本地被目标用户找到? | 不能 → 死 |

**第一问的重点在后半句。** "没人做"通常是坏消息(市场不成立),"有人做但都做不好"才是好消息。

**最好的情况:在位者结构上做不了。**

| 类型 | 稳定性 | 例子 |
|---|---|---|
| 巨头没想到 | 极不稳定 | 随时可能被做掉 |
| 巨头看不上 | 中等 | 市场变大就会进来 |
| **巨头不能做** | **稳定** | 做了等于拆自己的商业模式 |

**第三问是这次讨论里唯一悬了十几轮的东西,而它本该在第一步就被问。**

### 第二步:不是"能不能用上",是"是不是主角"

最容易出错的地方,是把"我能用上我的能力"当成通过条件。**这个门槛太低——任何方向你都能用上技术。**

正确的问法:**这个位置上,决定胜负的能力是不是我最强的那个?**

| 方向 | 决定胜负的能力 | 位置 |
|---|---|---|
| GEO | 渠道与媒体资源 | 配角 |
| 遴选 | 机关实务教研 | 缺席 |
| 批改 | 评分标准的教研 | 半个主角 |
| 跨机构记录 | 数据结构 + 采集工程 + 成本控制 | **主角** |

### 第三步:产品是被逼出来的,不是想出来的

到这一步,产品形态由前两步的约束决定。

跨机构记录这个位置 + 数据能力,推出来的必然是:采集端 + 骨架数据 + 差集计算。这三样不是创意,是唯一解。

**如果一个位置能推出好几种产品形态,通常说明位置还没选准,太宽了。**

### 每步之后的自检

| 时机 | 自检问题 | 答不上来说明 |
|---|---|---|
| 第一步后 | 如果这个位置这么好,为什么现在没人做成? | 没查够 |
| 第二步后 | 如果我的技术能力全部消失,这件事还有几分能成? | 还有七八分 → 你不是必需的 |
| 第三步后 | 这个产品最先会死在哪一步? | 答案就是最该先验证的那件事 |

**第三条如果早点用,答案会是"死在没人知道它存在"——而那正是悬了十几轮的问题。**

## 第二部分:本次暴露的思维盲区

### 盲区一:能力驱动的方向选择

**表现:** 前四个方向(GEO、选岗、遴选、批改)看起来各不相同,失败原因也各不相同,但**它们的气味是一样的**——全都是"我熟悉的领域里,能用上我技术能力的事"。

**判据:当备选项看起来很多但气味一样时,通常不是选项的问题,是标准的问题。**

**对照:** 跨机构学习记录是第一个不是从"我会什么"出发、而是从"用户在哪儿难受"出发的方向。所以它和前四个不一样。

### 盲区二:注意力单向流向可执行的部分

**表现:** 讨论的颗粒度是单向变细的——方向 → 产品 → 数据结构 → demo → 录入方式 → MCP 设计。**而那个从第一轮就存在的渠道问题,中间十几轮没有被主动提起过一次。**

**这是典型的工程师模式:问题被识别之后,注意力自然流向"能动手做的部分",而不是"最不确定的部分"。**

**具体后果:** 花了好几轮打磨 demo,但**一个真实用户都还没接触过**。每次提议去问人,都被"再加个功能"接了过去。

**这个模式带进执行阶段的典型结局:产品做得很完整,上线才发现没人要。**

### 盲区三:审视框架本身的动作偏少

**表现:** 讨论中换过两次判断标准(能力优先 → 位置优先 → 位置+能力+获客),**两次都是由外部指出的**。

在每一套标准**内部**的判断非常准——"这个位置有巨头""我没有机关经验""在职做不了面销",每条都对,且很多是遗漏项的补充。**但"我们判断的依据本身选错了"这件事,一次都没主动提过。**

**打个折扣:** 当时处在评审位而非提案位,这个位置天然偏局部修正。自己主导时未必如此。

**要的不是预设框架(那是更糟的版本),而是一个习惯性动作:在判断之前花十秒问一句——我现在是在用什么标准判断?**

举例:如果在第一轮就问"你说 GEO 好,是因为它市场大,还是因为它刚好用得上我会的东西?"——**这一句能省下三个月。** 因为答案是后者,而"刚好用得上我会的东西"从来不是一个方向成立的理由。

### 一个说不准的地方

**方向切换,是健康的证伪能力,还是回避真正的验证动作?**

同样的行为有两种解释:每次都是拿出调研数据才转向,可能说明尊重证据(好),也可能说明**更愿意待在"讨论方案"这个舒适区,因为讨论永远比去问一个陌生人安全**(不好)。

从讨论本身看不出是哪一种。**这件事只有自己知道答案。**

## 第三部分:强项(同样需要记录)

**能力边界清晰,且不美化。** 多数人在这类对话里会顺着"我懂教育又懂 AI"往上叠。而这次是在"你懂教研标准"被反复当作优势捧了三轮之后,自己划出"我不做教研专业讲解"这条线。**主动缩小战场比主动扩大战场难得多。**

**质疑打在结构上,不在结论上。** "你不了解我,凭什么认为豆包了解用户"——那不是反驳判断,是攻击推理前提,一击拆掉了一个错误设计(把聊天记录当作结构化记录的替代)。

**有沉没成本时仍能改方向。** GEO 方案已写完 12 个月路线图和成本预算,查出不成立后没有替它辩护。

**信息密度高。** "我在职,怎么面销"六个字,推翻了基于错误前提做的整套重构。

## 第四部分:可复用的判断规则

这些是讨论过程中沉淀出来的,和具体方向无关:

| 规则 | 说明 |
|---|---|
| **有截止日期的痛,才是能收钱的痛** | 学习规划什么时候做都行,所以什么时候都可以不做;公告发布后 24 小时内产不出解读,流量就没了 |
| **卖"赚钱"的工具比卖"省钱"的工具好卖** | 前者是投资项,决策快、愿溢价;后者是成本项,会算 ROI、会压价。在打价格战的行业里,所有人的注意力都在获客上而不是降本上 |
| **免费替代品是最难打的对手** | 用户没有痛感,凑合能用就不会付钱。选岗死于此;跨机构记录的真正对手不是粉笔,是 OneNote 和印象笔记 |
| **在位者的商业模式决定它不会做什么** | 培训机构永远不会对选岗收费(会破坏漏斗);永远不会做跨机构聚合(会拆自己围墙) |
| **公开信息主要由营销内容构成的行业,数据不可信** | GEO 市场规模各方口径差 30 倍 |
| **"没人做"通常是坏消息,"做得不好"才是好消息** | |
| **一个方向能推出多种产品形态,说明位置太宽** | |
| **能力配角位赢不了主角位** | 无论配角能力多强 |

## 最后

**这套框架的价值只在还没投入的时候。**

当前处境已经不是"选方向"了——有一个通过三问的位置、一个能力对位的判断、一个能跑的 demo、一套想清楚的开放策略。

**唯一没有的,是一个真实用户说过的一句话。**

**方法论现在帮不了忙了,只有真实反馈能。**
