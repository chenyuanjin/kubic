# 产品模块脑图

## 零 · 本文是什么 · 怎么打开

- **整份文件就是一张脑图的源。** 用 markmap 打开是可折叠、可缩放的脑图；不装任何东西打开，
  它是一份可读的缩进大纲 —— 两种读法内容完全相同。**图坏了内容不跟着坏**，这是选它的第一条理由
- **本文只回答「有什么、挂在谁下面」**
  - 凡是有方向的东西 —— 流程、状态、转移条件、失败分支 —— **一律不进本文**，
    在 [`23`](23-模块A-骨架层.md)–[`27`](27-模块E-出口层.md) 各模块文档里，图一律用 Mermaid
  - 两种图各管一件事，这条边界是为了本文不再长成一张什么都塞的大图
- **一个字段、一个数字、一条判据都不定义**
  - 模块名全部取自既有文档，不发明
  - 节点后的 `｜关卡n` 取自 [`08`](../execution/08-总路线图.md) 待办树的编号，不自行判定
- **基线**：`origin/v1` @ `afab5a7`，fetch 于 2026-08-31T05:20Z
- **状态：活跃** ｜模块增删、或某模块的关卡归属被人裁定，本文与 `20` §三 在同一次改动内更新
- **本文对关卡 0 的贡献是零** ｜关卡 0 要的是 `1.1.4` 那两个每日数字（`04` §阶段0），画脑图一个数都不产生
- **怎么打开成脑图**
  - `npx markmap-cli docs/product/22-产品模块脑图.md`，或 VS Code 装 `markmap` 扩展后在本文右上角点预览
  - 不打开也不影响读 —— 下面就是全文
- **回索引**：[文档索引](../INDEX.md) ｜ 模块与关卡的对照表在 [`20`](20-产品模块地图与产品逻辑.md) §三
- ⚠️ **本文不用块引用（`>`）**
  - markmap 把块引用渲染成挂在标题下的游离节点，脑图会被头注污染
  - 该写的话一律写成列表项，让它成为树上一个有位置的节点

## B 采集层 · 减数的入口 ｜关卡0

## D 差集层 · 减法本身 ｜关卡1

- 盲区 = 骨架层 − 行为层 → `13` §1.4

  - 分子 = 有 ≥1 条已确认标签的节点
